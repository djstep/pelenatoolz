# Отчёт по пакету 1

## Помощник assertInProject

Файл: `src/features/memberships/assert-in-project.ts`, рядом с `requireProjectAccess`.

Поддерживает модели из схемы:

- `Scene`, `ScriptVersion`, `Location` — у них есть своё поле `projectId`.
- `ScriptComment` — проект через версию сценария (`scriptVersion.projectId`).
- `LocationPhoto` — проект через локацию (`location.projectId`).
- `ResourceItem` — проект через категорию (`category.projectId`).

Новая сущность добавляется одним значением в список имён и одним `case` со своим фильтром.

На вызов уходит один запрос: сколько из переданных id реально лежат в этом проекте. Повторы id отбрасываются. Пустой список — успех, запроса нет.

Если найдено меньше, чем уникальных id, функция бросает `new Error("Объект не найден")`. Так же отказывает `requireProjectAccess`: бросает ошибку, а не возвращает объект. Текст один и тот же, когда записи нет и когда она из чужого проекта.

Четвёртый аргумент — необязательный клиент транзакции `prisma.$transaction`, чтобы проверку можно было вызвать внутри неё.

В действиях, которые соседи оформляют как `{ error: "..." }`, эта ошибка ловится и возвращается тем же текстом. Удаление фото бросает ошибку, как соседние удаления в том же файле.

Для `import "server-only"` в зависимости добавлен пакет `server-only` (`package.json` и `package-lock.json`). Без него проверка типов этот импорт не находит.
