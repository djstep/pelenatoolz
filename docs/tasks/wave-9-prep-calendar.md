# ЧАСТЬ 1. ИНСТРУКЦИЯ

## Что получится

- Раздел «Календарь» в Препродакшне: месяц, неделя, список.
- **Свои события**: встреча, читка, выбор объекта, техпроход, примерка, грим-тест, репетиция, тест камеры, производственное совещание, другое. Поля: название, тип, дата, время или «весь день», место (текстом или объект из «Локаций»), участники (из «Команды» и актёров), цеха, заметка.
- **Подтягивается само** (только чтение, клик открывает источник): пробы с датой, выезды скаута с датой (если в скауте есть дата), подготовительные дни из КПП.
- Пересечения: если человек в двух событиях одновременно — предупреждение (сохранить можно).
- Фильтры: по типу, цеху, человеку. «Мои события» — где я участник (если аккаунт связан с человеком команды — иначе фильтра нет).
- Экспорт списка через конструктор колонок, печать недели.

**Чего не будет в этой волне.** Напоминаний на почту, подписки в Google/Яндекс-календарь (ICS-ссылка), повторяющихся событий. Всё это — отдельным шагом позже, если календарь приживётся.

- Миграции — только на ветках базы dev и e2e. На прод не применять.

## Шаг 0. Разбор (только чтение)

1. Даты в источниках: пробы (дата, время, место?), скаут (есть ли дата выезда), КПП (как хранится дата дня и тип «подготовительный»). Тип полей (дата без времени / время с поясом).
2. Часовой пояс: как система сейчас хранит и показывает время (вызывной, отчёты смены). Предложи: события со временем — `timestamptz` + часовой пояс проекта (если его нет — `Europe/Moscow` константой с пометкой в отчёте); «весь день» — дата без времени. Не смешивать.
3. Сетка: своя (месяц + неделя + список на CSS grid) или пакет. Если пакет — кандидаты с лицензией (только MIT/ISC/Apache, не платные версии), размер, тема (получится ли под переменные волны 5), касания на планшете. Моя склонность — своя сетка для месяца и списка, неделя со временем — только если своя выходит без потери качества; решу по твоему сравнению.
4. Команда и актёры: как выбрать участника (общий выпадающий список с поиском — компонент из `src/shared/ui`).
5. Модель (ниже) с поправками, вопросы.

## Шаг 1. Модель

- `PrepEvent`: `projectId`, `title`, `typeId`, `allDay`, `startDate`/`endDate` (весь день) или `startAt`/`endAt` (со временем), `locationText?`, `locationId?`, `note?`, кто создал.
- `PrepEventParticipant`: `eventId` + `crewMemberId?` | `actorId?` (ровно одно).
- `PrepEventDepartment`: `eventId` + `departmentId`.
- Типы событий: справочник проекта с начальным набором (встреча, читка, выбор объекта, техпроход, примерка, грим-тест, репетиция, тест камеры, производственное совещание, другое), цвет из набора переменных темы. Правка справочника — в Настройках, при праве редактирования календаря. Тип с событиями не удаляется (только скрытие).
- Окончание не раньше начала — проверка на сервере.

## Шаг 2. Экран

- Вид: месяц / неделя / список (сегменты волны 5), переход «сегодня», вперёд/назад. Выбранный вид и дата — в адресе (`?view=&date=`), чтобы ссылкой можно было поделиться.
- Месяц: до 3 событий в ячейке + «ещё N»; клик по дню — неделя или список этого дня.
- Неделя: «весь день» сверху, события со временем по часам (если утверждено на шаге 0), иначе — неделя списком по дням.
- Список: по дням, с пустыми днями свёрнутыми.
- Создание: кнопка + клик по пустому дню. Окно события — все поля, участники (команда и актёры, с поиском), цеха. Удаление — подтверждение. Несохранённые изменения — существующий механизм.

## Шаг 3. Подтягиваемые события

- Источники: пробы с датой, выезды скаута с датой (если есть), дни КПП типа «подготовительный». Только чтение, другой вид (контур или значок «из кастинга/скаута/КПП»), клик — переход на источник.
- Загрузка — одним запросом на диапазон видимых дат на источник, не по дню. Без копирования в таблицу событий.
- Переключатели в фильтрах: показывать пробы / скаут / КПП.

## Шаг 4. Пересечения, фильтры, экспорт

- При сохранении: если у участника есть другое событие (своё или подтянутая проба с ним), пересекающееся по времени, — предупреждение со списком, «Сохранить всё равно» / «Вернуться». События «весь день» пересекаются только между собой — не предупреждать о каждом совпадении с событием со временем.
- Фильтры: тип, цех, человек; состояние фильтров — в адресе.
- Экспорт списка за период — через конструктор колонок; печать недели — браузерная.
