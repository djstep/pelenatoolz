# Заготовка сметы — шаг 0: разбор

Ветка `feat/smeta-template` (от `origin/main`, `b821516`). Код и база не менялись — только этот файл.
Univer в проекте — версия 0.25.1 (`@univerjs/presets`, `@univerjs/preset-sheets-core`).

Коротко:
- Новая смета цеха — пустой лист с одной строкой заголовков, без строк, кодов и формул.
- Сервер ищет колонки по тексту заголовков. Формат кода **не проверяет**: любой непустой код до 32 знаков становится статьёй. Формат `ПРЕФИКС-NN.NN` использует только автокод в браузере.
- Отдельного справочника статей нет. «Справочник» — это сами статьи (`BudgetItem`), которые сервер собирает с основного листа. С цехом их связывает `departmentId`, а префикс (`Department.codePrefix`) нужен только автокоду.
- Сумму, Налог и Итого сервер всегда считает сам. В ячейках формулы ставит браузер, сервер их значения только сверяет.
- Univer умеет защищать диапазоны и вставлять строки программно. Но защита блокирует и программную запись через обычные функции, и вставку строк рядом с защищёнными ячейками (подробно в п. 5).

## 1. Как создаётся смета цеха и что в ней при создании

**Кто и откуда.** Кнопка «Создать смету» (`src/features/smeta/components/create-department-budget-button.tsx`) есть только у главы цеха. Она вызывает `createDepartmentBudgetAction` (`src/features/smeta/actions.ts:72`):
1. Проверка входа, цеха и права (`requireDepartmentEditor`: `requireProjectContext` → `assertInProject("Department")` → `canEditDepartmentSmeta`).
2. `createDepartmentBudget` (`src/features/smeta/queries.ts:178`). Если смета у цеха уже есть, возвращается её id. Вторую создать не даёт уникальный `Budget.departmentId`: ошибку P2002 сервер ловит и отдаёт уже существующую смету.
3. Книга строится функцией `createDepartmentWorkbookSnapshot` (`src/features/smeta/lib/templates.ts`) и делится на листы (`splitWorkbookToSheets`). В одной транзакции создаются `Budget`, `BudgetSheet` и `BudgetSheetData`, затем в `Budget.mainSheetId` записывается основной лист.
4. Запись в аудит: «Создана смета цеха …».

**Что в новой смете:**
- `Budget`: имя «Смета — <цех>», статус `DRAFT`, `revision = 0`, стили книги — один стиль `smetaHeader` (жирный, серый фон).
- Один лист «Смета» (`createMainSheetData`, `src/features/smeta/lib/main-sheet.ts:416`):
  - строка 1 — 10 заголовков: `Код статьи · Наименование · Ед. · Кол-во · Ставка · Дни/смены · Сумма · Налог, % · Налог · Итого` (колонки A–J);
  - 300 строк × 26 колонок, закреплена первая строка, заданы ширины колонок;
  - **больше ничего**: нет строк-статей, разделов, подытогов, формул и кодов.
- Статей (`BudgetItem`) нет — они появятся при первом сохранении основного листа.

Шаблон встроен в код и один на все цеха. От цеха в книге зависит только её имя. Загрузить шаблон из файла или настроить его по цеху нельзя.

В `workbook-model.ts` есть старый `createDefaultWorksheet` («Статья / Кол-во / Цена / Сумма» с примером). Его использует только запасной путь: лист без данных или книга без листов (`assembleWorkbookFromSheets`). Новая смета через него не создаётся.

**Как дальше появляются коды и формулы** (браузер, `smeta-spreadsheet-editor.tsx:703`, `onMainValuesChanged`). Глава вписал Ставку или Кол-во в строку с пустым кодом → редактор ставит следующий код (`nextCode`) и в пустые Сумму, Налог и Итого вписывает формулы (`rowFormulas`). Если глава сам стёр код, строка получает метку `smetaNoAutoCode` (служебные данные строки Univer), и автокод в ней больше не появляется.

## 2. Как сервер разбирает основной лист

Где: `analyzeMainSheet` (`src/features/smeta/lib/main-sheet.ts:274`) плюс проверки по проекту в `analyzeWithProject` (`src/features/smeta/queries.ts:304`). Запускается:
- при автосохранении, если изменился основной лист (`persistDepartmentBudget`);
- при открытии страницы (только проверки);
- при отправке и утверждении (`approval-queries.ts`).

**Колонки.** Ищутся по тексту в строке 1 (`HEADER_ROW = 0`), не по месту: регистр, пробелы и «ё/е» не важны. Нужны все 10 заголовков из п. 1. Порядок колонок любой, лишние колонки разрешены. Если заголовок встречается дважды, берётся первая колонка (и пишется предупреждение). Если хоть одного заголовка нет — лист «сломан»: статьи не обновляются, отправить и утвердить смету нельзя, а в редакторе есть кнопка «восстановить заголовки».

**Строки.** Разбираются строки 2…5001 (`MAX_MAIN_ROWS = 5000`). Числа берутся из сохранённого значения ячейки (`v`): если там формула, используется её посчитанный результат. Текст «1 500,50» тоже понимается.

**Формат кода, который понимает сервер.** Никакого. Код — это текст ячейки «Код статьи» без пробелов по краям, переведённый в верхний регистр (`normalizeCode`). Префикс цеха и вид `XX-NN.NN` сервер **не проверяет**.
- Шаблон `^<префикс>-(\d{2,3})\.(\d{2,3})$` есть только в `nextCode` (браузер, автокод). Он нужен, чтобы выбрать раздел и следующий номер. Коды другого вида автокод просто не учитывает.
- В цех «TR» можно вписать `ХУД-01.01`, `abc` или `1`. Если код не занят другим цехом проекта, это станет обычной статьёй цеха TR.

**Что происходит со «странной» строкой** (ничего не теряется молча, кроме разделов и подытогов):

| Строка | Что делает сервер | Видно главе? |
|---|---|---|
| Нет кода, есть только наименование (раздел) | пропуск, без проверки | нет (это нормально) |
| Нет кода, в «Сумме» или «Итого» формула `СУММ/SUM(A1:A9)` (подытог) | пропуск | нет (это нормально) |
| Нет кода, но есть Ставка (≠0) или число, вписанное вручную, в «Сумме» или «Итого» | пропуск + проверка `amount_without_code` | да, строка подсвечена |
| Нет кода, в «Сумме» не-СУММ-формула, Ставки нет | пропуск, **без проверки** | нет — единственный «тихий» случай |
| Код длиннее 32 знаков | пропуск + `code_too_long` | да |
| Код повторяется на листе | учитывается первая строка, остальные — пропуск + `duplicate` | да |
| Код уже занят статьёй другого цеха проекта (даже архивной) | пропуск + `duplicate` («занят в смете цеха …») | да |
| Код есть, наименования нет | пропуск + `code_without_name` | да |
| В Кол-во / Ставке / Днях / Налоге % не число | считается пустым + `not_a_number`, статья создаётся | да |
| Код любого вида (без префикса, чужой префикс, «abc») | **обычная статья**, без предупреждения | нет |
| Код есть, Ставки нет | статья с суммой 0 | нет |

Проверки **не мешают сохранению**: лист сохраняется всегда. Проверки видны в панели и подсветкой строк. Отправку и утверждение блокируют только «сломанные заголовки» и «нет ни одной статьи».

**Что сервер делает со статьями** (`syncItems`, `queries.ts:391`). Новый код → статья создаётся. Код изменился → статья обновляется. Код пропал с листа → статья уходит в архив (`archivedAt`), её связи остаются. Код вернулся → статья восстанавливается из архива. Код в проекте никогда не переходит к другой статье (`@@unique([projectId, code])`). Если код пропал, а по нему уже есть начисления или платежи, — проверка `gone_with_fact`. Если код вернулся из архива с фактом — `restored_with_fact`.

## 3. Справочник статей и кодов, связь с цехом

- **Отдельного справочника нет.** Нет таблицы «типовые статьи», «шаблон статей цеха» и т. п. (в `schema.prisma` из смет есть только `Budget`, `BudgetSheet`, `BudgetSheetData`, `BudgetItem`, `BudgetVersion`, `BudgetVersionLine`).
- **Справочник по факту — `BudgetItem`**: статьи, которые сервер собрал с основных листов. С цехом их связывает `departmentId`. Код уникален во всём проекте. На статьи по id ссылаются начисления, строки платежей, «статьи по умолчанию» актёра, ресурса и объекта, транспорт смены, строки отчёта смены (`budget-item-select.tsx`, `default-items-actions.ts`).
- **Префикс цеха** — `Department.codePrefix`: 2–6 заглавных букв или цифр, первая — буква (`CODE_PREFIX_PATTERN`, `src/features/departments/schemas.ts`), уникален в проекте. Его задают при создании и правке цеха. Используется только:
  - автокодом в редакторе (`nextCode(department.codePrefix, …)`);
  - для показа рядом с названием цеха (список смет, шапка редактора).
- Если префикс цеха сменить, старые коды не меняются и остаются статьями цеха. Автокод начинает новую нумерацию с новым префиксом.
- Пример из сида e2e: «Транспортный цех», префикс `TR`, статья `TR-01.01` (`scripts/e2e-seed.ts:193`).
- Формат автокода: `ПРЕФИКС-РР.НН`. РР — раздел: берётся от ближайшей строки выше с кодом этого цеха, иначе 01. НН — следующий свободный номер в разделе. Считаются коды листа и все коды цеха, архивные тоже, чтобы номер не использовался повторно. Номера двузначные, после 99 — трёхзначные.

## 4. Какие формулы считает сервер, а какие лежат в ячейках

**Сервер всегда считает сам** (`analyzeMainSheet`, округление до копеек):
- Сумма = Кол-во × Ставка × Дни; пустые Кол-во и Дни = 1; пустая Ставка → Сумма 0;
- Налог = Сумма × Налог % / 100; пустой Налог % = 0;
- Итого = Сумма + Налог.

В статью (`BudgetItem.amount / tax / total`) и в строки версии пишется только этот расчёт. Что стоит в ячейках Сумма, Налог и Итого, сервер не берёт. Если число в ячейке расходится больше чем на 0,005, появляется проверка `sheet_differs` («формула даёт …» или «вручную …»).

**В ячейках** (ставит браузер при автокоде, только в пустые ячейки — `rowFormulas`):
- Сумма: `=IF(rate="","",IF(q="",1,q)*rate*IF(d="",1,d))`
- Налог: `=IF(sum="","",sum*IF(pct="",0,pct)/100)`
- Итого: `=IF(sum="","",sum+tax)`

Правила те же, что у сервера. Буквы колонок берутся по текущим заголовкам. Глава может стереть эти формулы, вписать числа или свои формулы — сервер это примет и только предупредит о расхождении.

**Кол-во, Ставка, Дни, Налог %** сервер берёт как есть, из сохранённого значения ячейки: там может быть и формула (например, ссылка на другой лист). Сам сервер формулы не вычисляет. Он доверяет значению, которое посчитал Univer в браузере и сохранил в `v`.

**Подытоги** (`СУММ/SUM(X1:X9)` в Сумме или Итого без кода) сервер пропускает. В версии и выгрузке (`freezeSheetFormulas`, `version-snapshot.ts`) подытог по одной колонке пересчитывается по уже исправленным числам. Все остальные формулы при этом заменяются значениями.

## 5. Univer: защита ячеек и программная вставка строк (0.25.1)

**Защита есть, и проект её уже использует.** При открытии сметы у главы строка заголовков защищается (`smeta-spreadsheet-editor.tsx:917–943`):
`range.getRangePermission().protect({ name })` + `setPoint(Edit/Delete/ManageCollaborator, false)`.
У продюсера и «просмотра всех» вся книга только для чтения (`getWorkbookPermission().setReadOnly()`).

Что доступно (типы в `@univerjs/sheets/lib/types/facade/permission/`):
- **Диапазон** (`FRange.getRangePermission()`): `protect`, `unprotect`, `isProtected`; точки `RangeEdit`, `RangeView`, `RangeDeleteProtection`. Подходит, чтобы защитить колонку или блок ячеек.
- **Лист** (`FWorksheet.getWorksheetPermission()`): `protect`, `setReadOnly` / `setEditable`, отдельные точки `InsertRow`, `DeleteRow`, `InsertColumn`, `DeleteColumn`, `SetCellValue`, `SetCellStyle`, `Sort`, `Filter` и т. д., `canEditCell(row, col)`.
- **Книга**: `CreateSheet`, `DeleteSheet`, `InsertRow`, `DeleteRow` и т. д.

**Вставка строк программно — есть:** `FWorksheet.insertRowAfter / insertRowBefore / insertRows / insertRowsAfter / insertRowsBefore`, удаление — `deleteRow(s)`. Запись значений — `FRange.setValue / setValues / setFormula`. Метки строк — `setRowCustomMetadata` (уже используется для `smetaNoAutoCode`).

**Важные ограничения** (по коду `SheetPermissionCheckController`, `@univerjs/sheets/lib/cjs/index.js`; в браузере не проверял):
1. **Защита блокирует и программную запись.** Функции `setValue`, `insertRows…` и т. п. выполняют обычные команды Univer (`SetRangeValuesCommand`, `InsertRowByRangeCommand`). Проверка прав срабатывает перед каждой такой командой, и при запрете команда падает с ошибкой «have no permission». Значит, чтобы записать что-то в защищённые ячейки, есть три пути:
   - снять защиту → записать → поставить снова;
   - писать напрямую мутациями (`sheet.mutation.set-range-values`, `sheet.mutation.insert-row`): проверка прав их не трогает, но такие правки не попадают в «отменить / повторить», и всё нужно собирать самим;
   - готовить содержимое на сервере в JSON листа (так создаётся новая смета), а не в редакторе.
2. **Вставка строки проверяется по всей ширине соседней строки.** Сосед — строка, от которой вставляют: для «вставить ниже» это строка над новой, для «вставить выше» — сама выделенная строка. Если в ней есть хоть одна защищённая ячейка, вставка запрещена — и мышью, и программно. Если защитить, например, колонки «Код статьи», «Сумма», «Налог», «Итого» на всю высоту, глава **не сможет вставлять строки внутри сметы**. Удаление строк с защищёнными ячейками тоже запрещено. Перенос строк, вставка из буфера и автозаполнение поверх защищённых ячеек — тоже.
   - Побочное наблюдение: по той же логике уже сейчас «вставить строку ниже» на строке заголовков, скорее всего, запрещено, а «вставить выше» на строке 2 работает. Не проверял, ничего не чинил.
3. **Защита не сохраняется в базе.** Univer хранит правила защиты в `resources` книги, а сервер сохраняет только листы и стили. Правила нужно ставить заново при каждом открытии (сейчас так и сделано для заголовков). Как правило защиты ведёт себя при вставке строк выше или внутри (растягивается или сдвигается), по типам не видно — нужно проверить в браузере.
4. Защиту обходит любой, кто шлёт запрос на сервер напрямую. Поэтому всё, что важно (код из заготовки, суммы), нужно проверять на сервере. Защита в Univer — только удобство для главы.

**Другой вариант вместо защиты** — проверка ввода (выпадающий список кодов, запрет «чужого» ввода). Пакет `@univerjs/preset-sheets-data-validation` 0.25.1 лежит в `node_modules` только как зависимость `@univerjs/presets`, в `package.json` проекта его нет. Чтобы использовать его по-честному, нужно добавить зависимость, а это по правилам проекта — с разрешения владельца.

## 6. Что сломается у существующих смет при переходе на заготовку

Исходные условия: перед переездом на VPS база будет полностью очищена, реальных смет нет. Значит, **переносить и чинить старые сметы не нужно**: код переезда данных не пишем. Ломаются только тестовые сметы в Neon, пока Neon работает, и тесты.

Что заденет переход, в зависимости от того, что именно поменяет заготовка:

- **Если поменяются заголовки или их текст** (новые колонки, переименования):
  - у старых смет `findMainColumns` не найдёт колонку → лист «сломан» → статьи не обновляются, отправить и утвердить нельзя, кнопка «восстановить заголовки» допишет новые заголовки справа, но не перестроит лист;
  - выгрузка в Excel и на диск ищет колонки так же (`export-queries.ts` → `freezeSheetFormulas`) — у старых смет не встанут Сумма, Налог и Итого;
  - тесты: `e2e/c8-smeta-excel`, `c10-budget-drive-export`, `c12-budget-export-autosave` строят лист из `MAIN_HEADERS`; плюс `src/features/smeta/export-queries.test.ts` и `lib/export-department-xlsx.test.ts`.
- **Если код станет строгим** (только `ПРЕФИКС-NN.NN` или только коды из заготовки):
  - старые строки с «свободными» кодами станут ошибками. Если сервер начнёт их пропускать, статьи при следующем сохранении уйдут в архив. По тем, где есть начисления или платежи, появится `gone_with_fact`, а в плане/факте они станут «вне сметы»;
  - коды, занятые в проекте, не освобождаются никогда (архивные тоже): `@@unique([projectId, code])`. Новые коды заготовки могут столкнуться со старыми статьями того же проекта;
  - сид e2e (`scripts/e2e-seed.ts`: цех `TR`, статья `TR-01.01`) завязан на текущий формат кода. При смене формата сид нужно поправить. Тест `c6-project-drive-export` только создаёт цех с префиксом `ZVUK` — его заденет, только если поменяются правила префикса.
- **Если заготовка будет своей у каждого цеха или тип цеха задаёт префикс:** правка префикса цеха (`departments/actions.ts`, форма цеха) должна будет учитывать заготовку. Сейчас префикс можно сменить в любой момент, и старые коды остаются.
- **Если строки заготовки будут защищены** — см. п. 5.2: при защите на всю высоту колонок глава теряет возможность вставлять и удалять строки, а автокод (`setValue` и `setFormula` в защищённых ячейках) начнёт падать. Автокод придётся переделать: писать мутациями или снимать защиту на время записи.
- **Не сломается:**
  - утверждённые версии: в `BudgetVersion.sheetData` лежит готовый снимок листа без формул, строки версии ссылаются на статьи по id;
  - разница версий (`budget-diff`);
  - начисления, платежи и «статьи по умолчанию»: они ссылаются на статью по id, а не на строку листа;
  - импорт Excel: он добавляет только листы-черновики, основной лист не трогает.
- **Neon до очистки.** Сайт на Vercel смотрит в ту же базу. Если старые тестовые сметы там мешают, их можно удалить или пересоздать — но это массовое удаление данных, только с разрешения владельца. Если не трогать, старые сметы откроются, но могут показать «заголовки повреждены» (при смене заголовков) или ошибки кодов (при строгом формате).

## Замечено попутно (не чинил)

- В `schema.prisma` у `BudgetItem.sortOrder` написано «Номер строки на основном листе (с 1)», а пишется индекс строки с 0 (`row.row`). Выгрузка (`freezeSheetFormulas`) использует его как индекс с 0 — код согласован, неточен только комментарий.
- Возможный запрет «вставить строку ниже» на строке заголовков из‑за её защиты (п. 5.2) — по коду, в браузере не проверял.
- Нет проверки, что код статьи начинается с префикса своего цеха: в цех можно завести статью с чужим префиксом, если такой код ещё не занят.
