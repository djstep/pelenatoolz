## 7. Шаг 6 — вырезанные сцены

Подробно — `WAVE_2V_NOTES.md`, раздел «Шаг 6». Коротко:

- **Перенумерация.** Номера вырезанных не меняются и не отдаются живым сценам (авто — пропуск,
  ручная — отказ с подсказкой буквы «например, 2А»). Без права — «Недостаточно прав» ответом.
- **Обмен номеров** — через временные значения в одной транзакции (`'~' || id`, затем новые номера).
  Отложенная проверка уникальности отклонена: нужна миграция (уникальность сейчас — индекс, а
  отложить можно только ограничение), и Prisma не умеет записать `DEFERRABLE` в схему.
- **Отчёт смены.** Вырезанная сцена не в дне — факт не пишется (ни новый, ни правка строки).
- **Удаление.** Сцена в дне КПП или в отчёте смены — отказ целиком с номерами, в окне до нажатия
  и повторно на сервере. Слот дня — не повод. Без миграции.
- Тесты: `script/lib/scene-numbers.test.ts`, `script/lib/scene-delete.test.ts`,
  `reports/lib/cut-scene-fact.test.ts`.

## 10. Находка 3: утверждение кандидата без фин. правки

**Решение владельца.** Для пользователя **без** фин. правки источника (кастинг — фин. правка
актёров, скаут — фин. правка объектов):

| У кандидата | Утверждается | Ставка / условия актёра (стоимость площадки у объекта) и снимок |
|---|---|---|
| заполнено | кто угодно | переносится от кандидата, как раньше (вносил человек с фин. правами) |
| пусто | **тот же** человек / та же площадка | прежние значения сохраняются, не стираются |
| пусто | **другой** человек / другая площадка | пусто — ставка прежнего не наследуется |

С фин. правкой — без изменений: всё как у кандидата, пустое стирает.

«Тот же» — по id, не по имени:
- **кастинг** — `personId` кандидата совпадает с человеком ранее утверждённого на эту роль кандидата
  (`Character.sourceCastingCandidateId`), и актёр роли уже есть;
- **скаут** — для каждого игрового объекта отдельно: этот кандидат уже утверждён для объекта
  (`Location.sourceScoutCandidateId`).

Ставка и условия решаются по отдельности (у кандидата есть ставка, но нет условий — ставка
переносится, условия того же человека остаются). Пустые условия из пробелов считаются пустыми.
Право берётся из серверного контекста (`ctx.canFinanceWrite`), из браузера по-прежнему только id.
Прочие фин. поля актёра (налог, переработки, доп. выплаты) утверждение не трогало и не трогает.

Файлы: `preproduction/lib/approve-finance.ts` (правило), `approve-casting.ts`, `approve-scout.ts`,
вызовы в `casting/actions.ts`, `scout/actions.ts`. Тесты: `preproduction/lib/approve-finance.test.ts`
(три случая для кастинга и скаута + «с фин. правкой как раньше»), `approve-casting.test.ts`.

объект, 2 площадки): все 9 проверок прошли; записи созданы и удалены (счётчик — 0).
