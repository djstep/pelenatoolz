### 4. Печать: один шаблон

- Сборка на сервере: чистая функция `модель → HTML-строка` (`escapeHtml`, `PRINT_HTML_CSP_META` первой строкой, без скриптов и `onclick`).
- **Просмотр** — тот же HTML в `<iframe srcDoc sandbox>`: стили листа не смешиваются со стилями сайта, лист белый в обеих темах.
- **Печать / PDF** — действие отдаёт HTML, окно — как в кастинге: `window.open` → `document.write` → `printWhenImagesSettled`. Шрифт из `data:` картинкой не считается — перед печатью нужно ждать `document.fonts.ready` (добавить в общий `printWhenImagesSettled`, другим выгрузкам не мешает).
- **Шрифт** IBM Plex Sans: в проекте файлов нет (сайт берёт его через `next/font/google` при сборке). Лицензия SIL OFL 1.1 — класть в репозиторий и раздавать можно, рядом текст лицензии; самим не резать (сабсет = изменённая версия). Нужны готовые woff2 от IBM (400, 600, 700; латиница + кириллица) + `OFL.txt` → см. вопрос 1. В HTML — `@font-face` с `data:font/woff2;base64` (работает во вкладке, в iframe и в Chromium `setContent`; CSP не мешает). Чтение файлов на сервере — `fs` + `outputFileTracingIncludes` в `next.config.ts`, чтобы файлы попали в сборку Vercel / standalone.
- **Страницы:** `@page { size: A4; margin: … }`; лист 2 — `break-before: page` у плана (не влезшее на лист 1 уходит на лист 2 перед планом само); `thead { display: table-header-group }` — шапка таблицы повторяется; `tr { break-inside: avoid }` — строка сцены не рвётся; шапка блока — `break-after: avoid`. Подвал «лист N из M» — поля страницы `@page { @bottom-right { content: counter(page) " из " counter(pages) } }`: Chrome печатает их с версии 131. В просмотре на экране страниц нет — подвал один, внизу листа.
- **Chromium на своём сервере:** `page.setContent(html)` → `page.pdf({ format: "A4", printBackground: true, preferCSSPageSize: true })`. Шаблон менять не нужно: шрифты внутри HTML, скриптов нет, поля страницы Chromium печатает сам. Нужен пакет `puppeteer`/`playwright` (или Gotenberg в Docker); системные кириллические шрифты не нужны — свои внутри HTML.
- **Excel:** маршрут `GET /api/projects/[projectId]/call-sheets/[dayId]/xlsx` — проверка входа и права внутри, ExcelJS пишет в поток → `Response(ReadableStream)`, `Content-Disposition: attachment`. Все строки — через `excelSafe` (сейчас вызывной его не использует). Конструктора колонок у вызывного нет — правило раскладки выгрузок не применяется.

### 5. Спецтранспорт и статья сметы

- Спецтранспорт — `ShootDayTransport`, правится только в вызывном. В отчёт смены попадает строкой `TRANSPORT` (`reports/lib/sync-work-rows.ts:265`) без актёра, позиции и объекта → `budgetItemFor` (`reports/lib/sync-accruals.ts:134`) возвращает `null` → «без статьи».
- **Важно:** начисления не создаются один раз — их пересчитывает каждое сохранение строки отчёта и «Обновить из КПП», и статья переписывается (если начисление не правили руками). Без защиты новая статья пропишется и в старые начисления.
- **Ещё важнее:** спецтранспорт сохраняется «удалить всё + создать» — у строк каждый раз новые id. После «Обновить из КПП» старые строки отчёта удаляются, начисления обнуляются, введённые км пропадают. Происходит уже сейчас.

**Рекомендую вариант (а) — статья у строки спецтранспорта:**
- миграция (только добавление): `ShootDayTransport.budgetItemId` (→ `BudgetItem`, `SetNull`), `ProductionReportWorkRow.budgetItemId` (снимок для строки спецтранспорта);
- выбор статьи — `BudgetItemSelect` в строке; проверка на сервере — `checkBudgetItemsUsable` (видимые сметы, не архив; уже стоящую можно оставить); менять статью — с фин. правом, как у ставки;
- сохранение спецтранспорта — по `id` (обновить / создать / удалить), без пересоздания;
- статья попадает в строку отчёта **только при создании строки**, в начисление — **только при создании начисления**. Существующие строки и начисления «без статьи» не меняются.

Вариант (б) (привязка к позиции ресурса) отклоняю: строка стала бы ресурсом во всей логике (ведомость склеит её с ресурсом «на смену», права по категории), и при обновлении старые начисления сразу получили бы статью.

### 6. Сцены дня и `Scene.cutAt`
