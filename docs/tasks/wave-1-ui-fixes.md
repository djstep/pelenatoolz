## Как идёт работа

Пять задач, каждая отдельным шагом. После каждой Claude Code останавливается, показывает итог и ждёт «дальше». Между шагами проверяй руками.

| Шаг | Что | Как проверить руками |
|---|---|---|
| 1 | Кнопки в комментариях сценария | Открыть комментарий, попасть по галочке и крестику без прицеливания |
| 2 | Свой тип договора в выпадающем списке | В форме договора открыть список типов, создать новый прямо там, он выбрался |
| 3 | Права на договоры по ролям | Завести роль «только просмотр договоров», зайти вторым аккаунтом: видит, но не может менять. Кнопок правки нет, прямые действия тоже отказывают |
| 4 | Светлая тема | Пройти все разделы в светлой теме. Ничего серого и нечитаемого. Тёмная тема не сломалась |
| 5 | Предупреждение о несохранённых изменениях | В карточке что-то поменять и закрыть крестиком, Esc, кликом мимо, переходом в меню, закрытием вкладки — везде предупреждение |

## Что разрешать Claude Code

- Правки кода, `tsc`, `eslint`, `build`, коммиты в рабочую ветку — да.
- Миграция для задачи 3 (если права на договоры потребуют изменения схемы) — да, но только через файл миграции, не `db push`. Перед применением пусть покажет `prisma migrate status`.
- `git push` и слияние в `main` — только после твоей ручной проверки всех пяти шагов.

## Задача 2. Свой тип договора — внутри выпадающего списка

Где: форма договора, поле «Тип договора». Сейчас свой тип добавляется отдельно.

Сделать:
- Найди компонент выбора с быстрым созданием, который уже используется для компаний и контрагентов (`entity-picker` или аналог). Используй его для типа договора: в выпадающем списке пункт «+ Добавить тип», ввод названия прямо там, после создания тип сразу выбран.
- Старый отдельный способ добавления типа убери из формы. Если типы ещё где-то редактируются (настройки, справочник), это место оставь.
- Сервер: создание типа — только с правом на изменение договоров (после задачи 3 — новым правом), с `assertInProject` и записью в аудит.
- Повтор названия в рамках проекта не плодит дубль: если тип с таким именем (без учёта регистра и пробелов по краям) уже есть, выбирается он.

## Задача 3. Права на договоры по ролям

Нужно: в настройках роли отдельно задавать «Договоры — просмотр» и «Договоры — изменение». Роль может видеть договоры, но не менять их.

Сначала выясни и покажи мне:
- как сейчас устроена матрица прав (разделы и флаги), где она хранится и как проверяется;
- какое право сейчас нужно для просмотра и изменения договоров и актов;
- нужна ли для нового раздела миграция схемы или матрица хранится так, что раздел добавляется кодом.

Предложи вариант и жди «дальше». Требования к решению:
- Отдельный раздел «Договоры» в матрице прав с флагами просмотра и изменения. Акты (certificates) — в этом же разделе, если в коде они живут рядом с договорами; иначе предложи.
- Существующие роли при переходе не должны ничего потерять и ничего лишнего получить: новые флаги заполняются из тех прав, по которым договоры открывались до этого.
- Продюсер — полный доступ, как и раньше.
- Проверка на сервере во всех действиях и на всех страницах договоров и актов: просмотр — для чтения, изменение — для создания, правки, удаления, смены статуса, загрузки файлов, создания типов, статусов и тегов.
- В интерфейсе без права изменения кнопки правки скрыты или неактивны, формы только для чтения.
- Финансовые суммы в договоре: если сейчас для них отдельно нужно финансовое право — это правило сохраняется.
- Правила пакета 5 (нельзя выдать больше, чем имеешь) должны работать и для нового раздела.
- Каждое изменение прав по-прежнему пишется в аудит.

## Задача 4. Светлая тема

Проблема: часть экранов покрашена жёстко под тёмную тему. В светлой теме фон остаётся тёмным или серым, текст нечитаем. Пример — КПП: `docs/tasks/img/kpp-light.png` (тёмные колонки дней и карточки сцен, текст заголовков сцен почти не виден).

Сначала:
1. Выясни, как в проекте устроены темы (CSS-переменные, класс `dark`, токены Tailwind 4 и т.п.).
2. Найди по коду все жёстко заданные цвета, которые не следуют теме: фиксированные тёмные фоны и градиенты, `text-white`/`text-black` на фонах темы, hex/rgb в стилях и `style={{}}`, классы без пары для светлой темы.
3. Покажи мне список экранов и компонентов с проблемой, жди «дальше».

Потом исправь:
- Цвета — через токены темы, а не новые жёсткие значения.
- Цвета со смыслом (типы дней КПП: рабочий, выходной, отсыпной, подготовительный; статусы либретто; цвета категорий) должны оставаться различимыми в обеих темах. Для светлой темы подбери светлые фоны с тёмным текстом той же гаммы.
- Контраст текста к фону — не ниже 4.5:1 для обычного текста.
- Тёмная тема должна выглядеть как раньше.

Проверка: сам пройди в браузере все разделы проекта в светлой и тёмной теме, сделай скриншоты. В итоге шага — список проверенных экранов: что было, что стало.

## Задача 5. Предупреждение о несохранённых изменениях

Нужно: в любой карточке и форме, где есть кнопка «Сохранить», при попытке закрыть с несохранёнными изменениями (новая запись или правка старой) появляется предупреждение.

Сначала составь и покажи опись: все карточки, окна, боковые панели и страницы-формы с кнопкой сохранения. Отметь, где есть автосохранение (смета, редактор сценария и т.п.) — им предупреждение не нужно.

Решение — один общий механизм, а не своё в каждой карточке:
- «Есть изменения» = текущие значения формы отличаются от исходных. Вернул как было — предупреждения нет.
- Ловить: крестик, Esc, клик мимо окна, кнопку «Отмена», переход по меню и ссылкам внутри программы, закрытие и перезагрузку вкладки.
- Окно предупреждения: «Есть несохранённые изменения» и кнопки «Остаться» и «Не сохранять». Кнопку «Сохранить» в окне добавь, если сохранение карточки можно вызвать без доработки её логики; если нет — не добавляй.
- Для закрытия вкладки — штатное предупреждение браузера.
- Кнопку «назад» в браузере перехватывай, если это получается надёжно; если нет — скажи мне.
- После успешного сохранения флаг изменений сбрасывается.

Внедрение двумя частями:
- 5а — механизм и основные карточки: договоры, акты, контрагенты, компании, актёры, персонажи, сцены, платежи, начисления, локации. Стоп, проверка.
- 5б — все остальные из описи.
