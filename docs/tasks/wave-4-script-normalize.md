# ЧАСТЬ 1. ИНСТРУКЦИЯ

## Что получится

- Сценарий в любом виде (docx со стилями, docx без стилей, fdx, fountain…) при импорте приводится к одному стандарту: сцены, шапки, персонажи, реплики, ремарки, переходы.
- Без ИИ: правила плюс экран проверки.
- Экран проверки показывает только то, в чём система не уверена: «МАМА и Мама — один персонаж?», «шапка без ИНТ/НАТ», «сцены без номеров — пронумеровать?».
- Словарь проекта запоминает твои ответы. При следующем импорте и новой версии сценария те же вопросы не повторяются.
- Хронометраж считается по нормализованному тексту, поэтому одинаково на любом исходнике.

## Подготовка

1. Положи в проект `docs/tasks/fixtures/scripts/` из пакета: три твоих сценария (`ddct.docx`, `moya-malenkaya-draft.docx`, `moya-malenkaya-v4.docx`). На них Claude Code напишет автотесты.

## Как проверить руками

- Импортировать тот же файл второй раз (как новую версию): старые вопросы не повторяются.
- Импортировать свой «самый кривой» сценарий, которого нет в тестах. Это главный экзамен.

### 1. Определение типов блоков — три уровня

**Уровень 1. Стили Word.** Словарь названий стилей (без учёта регистра):
- английские: SCENE HEADING, ACTION, CHARACTER, DIALOGUE, PARENTHETICAL, TRANSITION, SHOT, GENERAL;
- русские: «Заголовок сцены», «Описание действия», «Имя героя», «Реплика», «Ремарка», «Переход», «Персонажи» (служебная строка со списком персонажей сцены).
Словарь расширяемый (константа в коде).

**Уровень 2. Отступы.** Если стилей нет (всё в «Обычном»), собрать частоты левых отступов абзацев и найти профиль. Пример из `moya-malenkaya-draft.docx`: имя персонажа ≈ 5,6 см, ремарка ≈ 4,1 см, реплика ≈ 2,5 см, действие — без отступа. Шапка сцены — жирный абзац без отступа с ИНТ/НАТ. Профиль ищется по файлу, а не задаётся числами.

**Уровень 3. Текст.** Если нет ни стилей, ни отступов: шапка — строка с ИНТ/НАТ (в любом регистре, с номером или без); персонаж — короткая строка в верхнем регистре (с расширениями в скобках) перед репликой; ремарка — текст в скобках; переход — CUT TO:, FADE TO BLACK, СМЕНА КАДРА, ЗТМ и т.п.; всё остальное — действие.

Уровни проверяют друг друга: если стиль говорит «персонаж», а текст похож на шапку — это вопрос на экран проверки.

### 2. Нормализация

**Титульная страница.** Всё до первой шапки сцены, отцентрированное или с большими отступами, — не сцены, а метаданные: название, автор, версия, дата. Показать их на экране проверки, сохранить в версию сценария.

**Шапка сцены** → номер · ИНТ/НАТ · объект · подобъекты · режим · пометка.
- Номер: `1.`, `1`, `Сц. 1`, `СЦЕНА 1`, с буквой (`11А`, `11a`). Сцен без номеров в файле — предложить пронумеровать подряд (вопрос).
- ИНТ/НАТ: ИНТ, ИНТ., ИНТЕРЬЕР, INT, INT., НАТ, НАТ., НАТУРА, EXT, а также ИНТ/НАТ, НАТ/ИНТ, ИНТ-НАТ. Без учёта регистра (`инт.`, `ИНт.`).
- Объект и подобъекты: разделители `. ` (точка с пробелом и без), `/`. Пример: `ДОМ. ДЕТСКАЯ` → объект «ДОМ», подобъект «ДЕТСКАЯ»; `Квартира/спальня` → «КВАРТИРА» / «СПАЛЬНЯ».
- Несколько мест в одной сцене: ` / ` между подобъектами в драфте (`ДОМ. ДЕТСКАЯ / КОРИДОР`) и `///` в версии 4.0 (`Квартира/спальня///коридор`) → у сцены несколько подобъектов одного объекта. В модели сцены уже есть связь с несколькими локациями — используй её.
- Режим: после ` — `, ` – `, ` - ` или в конце строки. Словарь: УТРО, ДЕНЬ, ВЕЧЕР, НОЧЬ, РАССВЕТ, ЗАКАТ, СУМЕРКИ, РЕЖИМ (расширяемый). Пометки: ПОЗЖЕ, НЕМНОГО ПОЗЖЕ, СЛЕДУЮЩЕЕ УТРО, ПРОДОЛЖЕНИЕ, (ПОЗЖЕ) — сохраняются как пометка; если пометка стоит вместо режима («— ПОЗЖЕ»), режим берётся у предыдущей сцены, и это вопрос на экран проверки.
- Регистр и мусор: приводить к верхнему регистру, убирать двойные и неразрывные пробелы, хвостовые пробелы, разные тире к одному.
- Шапка без ИНТ/НАТ (`1. ЗАКАДРОВЫЙ ГОЛОС`) — вопрос: это сцена или пометка.
- Пустые шапки и шапки из одного номера (`37. `) — выбросить, сказать на экране проверки.

**Персонажи.**
- Имя без расширений в скобках: (З.К.), (ЗК), (З/К), (ВПЗ), (ПРОД.), (ПРОД), (V.O.), (O.S.), (CONT'D), (за кадром). Со скобкой вплотную тоже: `ВИКТОРИЯ(ЗК)`, `ЮРИЙ(ВПЗ)`. Расширение сохраняется у реплики, но не создаёт нового персонажа.
- Верхний регистр, ё = е при сравнении, лишние пробелы.
- `(ДАЛЬШЕ)` и похожее как отдельная строка-«имя» — это не персонаж, а пометка продолжения.
- Цифра в конце (`СТАЖЕР1`) — вопрос: «СТАЖЁР 1» или опечатка «СТАЖЁР».
- Возраст при первом появлении в действии (`ВИКТОРИЯ(27)`, `АННА (5)`) — предложить записать как возраст персонажа.
- Строка «Персонажи» под шапкой (версия 4.0) — список персонажей сцены. Сверить с теми, кто говорит в сцене; расхождения — вопрос.
- Пустые абзацы со стилем персонажа — выбросить.

**Реплики и ремарки.** Несколько абзацев реплики подряд — одна реплика. Ремарка может стоять внутри реплики, не только перед ней. Ремарка без персонажа перед ней (`(пауза)` после реплики) — продолжение реплики предыдущего персонажа.

**Переходы.** CUT TO:, FADE TO BLACK, FADE OUT, СМЕНА КАДРА, ЗТМ, ВЫХОД ИЗ ЗТМ — тип «переход».

### 3. Похожие имена — предложения объединить

Для персонажей и локаций: совпадение после нормализации; расстояние редактирования ≤ 2 при длине ≥ 5; одно — начало другого («МАША» / «МАША ПЕТРОВА»); совпадение с уже существующими в проекте. Это только предложения — решает пользователь.

### 4. Экран проверки

- Группы: Титульная страница · Сцены (нумерация, шапки с вопросами) · Персонажи (объединить? новый?) · Локации (объединить? новый?) · Нераспознанные блоки.
- Каждый вопрос — один клик: принять предложение, отклонить, выбрать из существующих.
- «Принять все предложения» для группы.
- Сравнение «было → стало» для любой сцены.
- Ничего не пишется в базу до «Импортировать».

### 5. Словарь проекта

- Хранит решения: «МАРИЯ → МАША», «КВ. ИВАНА → КВАРТИРА ИВАНА», «ЗАКАДРОВЫЙ ГОЛОС — не сцена» и т.п.
- Применяется молча при следующих импортах и новых версиях. Экран проверки показывает только новое.
- Экран словаря в настройках проекта: посмотреть, удалить ошибочное правило.
- Аудит изменений словаря.
