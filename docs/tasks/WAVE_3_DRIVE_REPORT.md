## Время функций на Vercel (`maxDuration`)

`export const maxDuration = 60` (route segment config) задан там, откуда идут выгрузка на диск, OAuth дисков и пересчёт доступов после ответа (`after()` живёт в той же функции, что и действие):

- страницы (действия на странице получают её предел): вызывной дня `projects/[projectId]/call-sheets/[dayId]`, «Настройки проекта» `settings`, «Участники» `members`, «Роли» `roles`, «Цеха» `settings/departments`, «Профиль» `profile`, принятие приглашения `invite/[token]` (принятие тоже запускает пересчёт доступов);
- маршруты: `/api/cloud/google/authorize`, `/api/cloud/google/callback`, `/api/cloud/yandex/authorize`, `/api/cloud/yandex/callback`.

Пределы Vercel (по [документации Vercel](https://vercel.com/docs/functions/limitations), ноябрь 2026):

| Тариф | Fluid compute (включён по умолчанию у проектов с 23.04.2025) | Без Fluid compute (старые проекты) |
|---|---|---|
| Hobby | по умолчанию и максимум — 300 с | по умолчанию 10 с, максимум 60 с |
| Pro | по умолчанию 300 с, максимум 800 с | по умолчанию 15 с, максимум 300 с |

60 с допустимо на любом тарифе и в любом режиме. Без Fluid compute это **поднимает** предел (иначе Hobby оборвал бы выгрузку через 10 с); с Fluid compute — **опускает** с 300 до 60 с на этих страницах. Проверить в Vercel → Project → Settings → Functions, включён ли Fluid compute; если включён и пересчёты доступов на проде не успевают (строки «не успели» в «Не синхронизировано»), предел можно поднять (например, до 120 с) — это одна строка в каждом файле.

## Известные ограничения и риски

1. **Файлы — в аккаунте хранителя.** Ушёл человек — папки, файлы и выданные доступы остались у него, система ими больше не управляет. Лечится служебным аккаунтом компании (подсказка при подключении).
2. **Персональные данные за границей.** В вызывном — телефоны людей, Google — иностранный сервис. После переезда в РФ (152-ФЗ, трансграничная передача) — вопрос к юристу. Решение — за владельцем.
3. **Google с сервера в РФ** после переезда на VPS может работать со сбоями — код даёт понятную ошибку («Диск отвечает слишком долго…»), не падает.
4. **Опечатка в «Почте для Google»** — вызывной уйдёт постороннему. Смягчение: в «Профиле» видно, на какую почту выдаётся доступ, и предупреждение о несовпадении с подключённым Google.
5. **Не пересоздавать OAuth-клиент Google** — с `drive.file` приложение потеряет доступ ко всем созданным им файлам и папкам.
6. **Смена `CLOUD_TOKEN_SECRET`** — все диски, включая диск проекта, переподключать.
7. **Наследование доступов Google**: доступ выдаётся только конечным папкам («Общая», папки цехов); любая будущая выдача родительской папке откроет все цеха. В коде — запрет и тест.
8. **Ручные доступы.** Выданное хранителем руками система не видит и не снимает: удалённый из проекта человек сохранит такой доступ. Если человеку уже выдан системный доступ, а хранитель выдал ещё и руками — у Google это один доступ, при снятии система снимет его.
9. **Замена содержимого Google Таблицы** (`files.update`) на реальном аккаунте не проверена. Если Google откажет — одна константа `GOOGLE_SHEET_REPLACE_MODE` → `"recreate"` (новый файл, старый в корзину, ссылка меняется). Комментарии после замены могут «отвязаться» от ячеек.
10. **Время на Vercel.** Выгрузка — до 50 с, транзакция — до 60 с (держит соединение с базой на это время), пересчёт доступов после ответа — до 40 с. Предел функции задан явно — `maxDuration = 60` (см. раздел «Время функций на Vercel»). Худший случай «выгрузка 50 с + пересчёт после неё» в 60 с не укладывается: Vercel оборвёт пересчёт, невыданное останется «не синхронизировано» и догонится следующим пересчётом или кнопкой.
11. **Одна выгрузка за раз на диск проекта.** Пока она идёт (секунды, до 60 с), отключение диска, удаление хранителя и обновление токена ждут её конца. Вторая выгрузка ждёт до своего предела — иначе «уже идёт выгрузка, попробуйте через минуту».
12. **Доступы — через несколько секунд после ответа** (`after()`); при лимите частоты Google — повторы, остаток — в «не синхронизировано». При десятках цехов пересчёт делает десятки запросов (укладывается в 40 с).
13. **Пересчёты не в очереди**: два пересчёта одного проекта могут идти одновременно; расхождение исправит следующий пересчёт или кнопка «Синхронизировать доступы».
14. **«Почта не Google»** — подсказка, не проверка: корпоративные почты на Google Workspace помечаются лишний раз.
15. **Яндекс:** выдать доступ конкретным людям API не позволяет — только личный диск, файл видит сам человек. Ссылка из окна ведёт на папку; если Яндекс вернёт путь в другом виде — на «Приложения» целиком.
16. **«Выйти из проекта»** самому — такого действия в системе нет; когда появится, вызвать там авто-отключение диска хранителя.
17. **Гонка двух отключений одного аккаунта** в одну секунду может оставить токен неотозванным (убирается в аккаунте Google руками); сломать живое подключение не может.
18. Плашка «диск проекта отключён» — один лишний запрос к базе на каждой странице проекта у продюсеров.

    → «Доступ к диску проекта есть».
12. Если тот же Google подключён и как личный: «Отключить» диск проекта.
    → Личный диск продолжает работать (п. 5 проходит); в «Сторонних приложениях» аккаунта Google приложение осталось. Потом отключите и личный → приложение пропало из «Сторонних приложений». Снова подключите диск проекта (п. 9) для пунктов ниже.
13. Отзовите доступ приложения в аккаунте Google руками → «Проверить доступ».
    → «Доступ отозван», плашка «нужно переподключить», запись в журнале. «Переподключить» → снова работает.
14. Под вторым продюсером (не владелец, не хранитель), если есть.
    → Раздел виден, кнопок «Заменить» / «Отключить» нет.

### Вызывной → «На диск…» — диск проекта

15. Окно «На диск…» под вами.
    → Видны «Мой Google Диск», «Диск проекта — Общая», «Диск проекта — папка цеха» и строки «Кто увидит».
16. Выгрузить в «Общую».
    → Ссылка открывает таблицу; на диске хранителя — `PELENA · <Проект> / Вызывные / Общая`.
17. Выгрузить в папку цеха.
    → `… / Вызывные / Цеха / <Цех>`.
18. Повторная выгрузка в «Общую».
    → Ссылка та же, «Уже на диске: … вы · время · версия».
19. Войдите в систему вторым аккаунтом (не продюсер) → окно «На диск…».
    → Нет чужих цехов; без права правки вызывных нет «Общей».
20. (Vercel) выгрузка на диск проекта.
    → Укладывается во время функции; если Google отвечает долго — «Диск отвечает слишком долго…», без ошибки 500.

### Google Диск — доступы к папкам

21. На диске хранителя → «Настройки доступа» у папок.
    → У «PELENA…», «Вызывные», «Цеха» — только вы; у «Общей» — участники с просмотром вызывных (комментаторы); у папки цеха — главы цеха и продюсеры.
22. Второй аккаунт (почта Google).
    → Пришло письмо от Google о доступе; открывает «Общую» и таблицу, может комментировать, не может править; папку чужого цеха не видит.
23. «Настройки проекта» → «Синхронизировать доступы».
    → Без ошибок (проверка, что Google отдаёт список доступов папки при `drive.file`), список «Не синхронизировано» пуст.

### Участники

24. «Участники»: у хранителя метка «Хранитель диска»; смена его роли и «Удалить».
    → Окно с предупреждением «Это хранитель диска проекта — диск отключится…» («Отмена» — ничего не меняется).
25. Снимите главу цеха / удалите участника (не хранителя).
    → Через несколько секунд его доступ у Google пропал; доступ, выданный вами руками, остался.

### Диск проекта отключён

26. «Отключить» диск проекта → окно «На диск…».
    → У не продюсера «Диск проекта не подключён — обратитесь к продюсеру», у вас — ссылка «Открыть настройки проекта»; выгрузка на личный диск работает.
27. Через 7 дней (режим Testing).
    → Личный диск и диск проекта показывают «доступ отозван — переподключите»; после переподключения всё работает, папки диска проекта (тот же аккаунт) сохранились.
