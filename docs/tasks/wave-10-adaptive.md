# ЧАСТЬ 1. ИНСТРУКЦИЯ

## Что получится

Система нормально работает на трёх классах устройств: телефон (от 375 px), планшет (768–1024, в руках на площадке, в обе ориентации), компьютер (1280+, включая широкие 1920+). Не «всё одинаково везде», а по матрице: что на каком устройстве должно работать полностью.

## Матрица (утверждаешь на шаге 0)

| Экран | Телефон | Планшет | Компьютер |
|---|---|---|---|
| Вход, регистрация, приглашение, список проектов | полностью | полностью | полностью |
| Вызывной (просмотр), явочный лист | полностью | полностью | полностью |
| Отчёт смены (ввод факта) | полностью | полностью | полностью |
| Карточка сцены, команда, календарь (список) | полностью | полностью | полностью |
| Либретто, кастинг, локации, актёры | просмотр + правка карточек; таблица — прокрутка внутри | полностью | полностью |
| КПП | просмотр по дням (список) | полностью, перетаскивание пальцем | полностью |
| Вызывной (правка), обзор, настройки | полностью, в одну колонку | полностью | полностью |
| Смета (Univer), редактор сценария, сравнение версий | только просмотр + плашка «редактирование — на компьютере или планшете» | полностью (смета — насколько даёт Univer) | полностью |
| Финансовые таблицы | просмотр, прокрутка внутри таблицы | полностью | полностью |

Логика: на площадке с телефона смотрят вызывной, звонят людям, отмечают явку и факт смены. Смету и сценарий с телефона не правят.

**Чего не будет.** Отдельного мобильного приложения и офлайн-режима. Функции не меняются: на телефоне ничего не исчезает тайно — где правка недоступна, есть плашка с объяснением.

## Подготовка

1. Волны 5–9 слиты (адаптируем всё, что есть).
2. Миграций нет.
3. Если есть реальные устройства — iPhone и iPad/Android-планшет для ручной проверки после шага 4.
4. Файл в `docs/tasks/wave-10-adaptive.md`, коммит в `main`. Новая сессия Claude Code.

## Правила волны

- Функции, тексты, права, данные не меняются. Миграций нет.
- Определение устройства — только CSS: ширина (`min-width`), `@media (pointer: coarse)`, `hover`. Никакого разбора user-agent. Брейкпоинты — те, что уже в Tailwind проекта; новые — только если нужно, с объяснением.
- Нигде нет горизонтальной прокрутки страницы. Широкая таблица прокручивается внутри своей карточки, первая колонка (номер/название) закреплена.
- На сенсорных устройствах (`pointer: coarse`): цель нажатия не меньше 40×40 px (визуально элемент может быть меньше — расширить область нажатия), действия по наведению продублированы видимой кнопкой или меню «⋯».
- Поля ввода на телефоне — шрифт не меньше 16 px (иначе iOS приближает страницу).
- Окна на телефоне — на весь экран (лист снизу или полноэкранное окно), кнопки действий закреплены внизу, учтены безопасные зоны (`env(safe-area-inset-*)`).
- Телефоны и почты — ссылки `tel:` / `mailto:` везде, где они показываются (команда, вызывной на экране, карточки актёров/кандидатов при праве).
- Где по матрице правка на устройстве не поддерживается — экран открывается на просмотр и плашка: «Редактирование доступно на компьютере или планшете». Не прятать данные.
- Не трогать вид печатных листов и файлов (вызывной, явочный, сценарий-бумага, Excel) — только экранные оболочки.
- Перетаскивание (КПП и другие места) — сенсор касания с задержкой долгого нажатия (≈ 250 мс), чтобы обычный свайп прокручивал. Проверить, какая библиотека перетаскивания стоит, и использовать её сенсоры.
- Новые пакеты — только после моего «да».

## Шаг 0. Замер (только чтение + скриншоты)

2. Таблица проблем: экран → ширина → что не так (прокрутка страницы, наложение, обрезка, мелкие цели, окно не помещается, ховер-only действие) → предложение.
3. Матрица из части 1 — сверить с реальными экранами, поправить, показать.
4. Плейрайт-проекты для устройств (`iPhone 13`, `iPad (gen 7)` и `iPad landscape`, `Desktop 1920`) — предложить, как добавить в конфиг без замедления обычного прогона (отдельная команда, например `npm run e2e:devices`).

Жди утверждения матрицы и «дальше».

## Шаг 1. Общее

Оболочка (меню, шапка вне проекта), `src/shared/ui` (окно, меню «⋯», выпадающие списки, поля дат и времени, тосты), общие классы таблиц, вкладки/сегменты (на узком экране — прокрутка вкладок или выпадающий список, спроси, если не очевидно).

## Шаг 2. Экраны «полностью на телефоне»

По матрице. Таблицы, которые на телефоне нужно читать, а не сравнивать (явочный лист, команда, отчёт смены), — можно показать карточками вместо строк на узкой ширине; та же разметка данных, другая раскладка. Покажи на одном экране, жди «да», потом остальные.

## Шаг 3. Планшет

КПП: перетаскивание пальцем (долгое нажатие), прокрутка доски и колонок дня без конфликта с перетаскиванием, «Без дня» — выезжающая панель в портретной ориентации. Либретто, кастинг — проверка по таблице проблем.

## Шаг 4. Тяжёлые экраны на телефоне

Смета, редактор сценария, сравнение версий: просмотр + плашка. Univer — проверить, что на телефоне хотя бы просмотр работает; если нет — плашка и кнопка «Открыть сводку» (если есть экран просмотра), спроси.

## Шаг 5. Широкие экраны, проверка, отчёт

1. 1920+: текстовые блоки и формы — ограничение ширины чтения, таблицы и КПП — на всю ширину.
2. Скриншоты после — `docs/tasks/ref/adaptive/after/`, та же сетка, что в шаге 0.
3. `npm run e2e` и `npm run e2e:devices` зелёные; горизонтальной прокрутки страницы нет ни на одной ширине (автоматическая проверка во всех тестах устройств).
4. `docs/tasks/WAVE_10_REPORT.md`: что сделано по шагам, таблица проблем «было → стало», места с плашками «на компьютере», что не удалось (особенно Univer), список для ручной проверки на реальных устройствах.
5. Не пушить и не сливать в `main`.
