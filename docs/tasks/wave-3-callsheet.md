## Общие правила волны

- Права — на сервере. Скрытая кнопка защитой не считается. Новые пункты меню — через `NavAccess`.
- Миграции — только файлами, перед применением `prisma migrate status`. Новые разделы и флаги прав — миграцией данных по образцу `20261029120100_smeta_all_permission_section`. `prisma format` и `db push` не запускать. Метку папки миграции проверить: позже всех существующих.
- **Открытие страницы ничего не пишет в базу.** Вызывной создаётся, обновляется из шаблона или из КПП только кнопкой, с правом правки.

- **Печать** — HTML из шаблона, через общие `escapeHtml`, `PRINT_HTML_CSP_META`, `safePrintUrl`, `printWhenImagesSettled` (`src/shared/lib/escape-html.ts`, `print-window.ts`). Своего экранирования и `onclick` внутри печатной страницы не заводить.

## Шаг 2. Все поля вызывного

Что можно — подтягивается автоматически и правится руками.

**Шапка и день**
- проект, дата (день недели — сам), номер смены, «день N из M» (если есть в КПП), версия вызывного;
- количество сцен и хронометраж дня — по плану съёмки;
- сбор группы: время и место (адрес) крупно;
- времена: начало и конец смены, репетиция, мотор, обед (с–по), стоп-мотор;
- погода: описание, t днём, t ночью — руками; восход и закат — сами, по координатам объекта (расчёт солнца уже есть);
- объекты дня: адрес, подобъекты с номерами сцен (сам из плана), отметка второго юнита;
- «Ограничения по актёрам» — текст;
- «Важно» — текст, выделенная плашка (пусто — плашки нет).

**Люди**
- руководители группы — из шаблона;
- вызов цехов — из шаблона, сортировка по времени;
- база и транспорт группы — из шаблона, по времени, «не нужен»;
- актёры: персонаж, актёр, сцены (из плана), транспорт («машина за актёром» / «сам» / свой текст), прибытие, костюм, грим, готовность, конец смены;
- групповка и дублёры: кто, кол-во, сцены, прибытие, готовность, конец.

**Элементы площадки** — одна таблица с разделами: игровой транспорт, реквизит, костюм, трюки, операторская техника, CG, спецтранспорт. Список разделов расширяемый. Колонки: что, сцены, прибытие, готовность, конец. Элементы — из разбора сцен дня (если размечены в либретто), добавляются руками.

**Спецтранспорт и статья сметы** — по варианту шага 0. Начисления спецтранспорта из отчёта смены получают статью так же, как у актёра и ресурса. Существующие начисления «без статьи» не трогать.

**План съёмки**
- строки двух типов: «сцена» и «служебная» (грим/освоение, репетиция, подготовка, обед, переезд, продолжение сцены N, свой текст);
- у строки: начало, длительность (конец считается); для сцены — номер, ИНТ/НАТ, объект, режим и день по сценарию, синопсис, персонажи, хронометраж — из либретто; элементы сцены по разделам; примечание;
- **вырезанные сцены** (`Scene.cutAt`) из дня КПП в план не подтягиваются. Если в дне КПП стоит вырезанная сцена — на экране правки предупреждение «В дне КПП стоит вырезанная сцена N — уберите её из дня в КПП». Руками вырезанную сцену в план не добавить (проверка на сервере);
- второй юнит — отдельная дорожка;
- итого хронометража по основному юниту.

**Схема объекта (без картинки)**
- у объекта (локации): точки — номер, название, описание (проходная/сбор, караван, площадка…);
- тексты «как добраться», «парковка», «на месте»;
- поле под картинку не заводить — картинка после переезда (запиши в отчёт, что для неё нужно).

- Порядок блоков:
  - **Лист 1:** шапка (проект, дата, смена, хронометраж + времена + крупно сбор и место) → строка «погода · объекты · важно/ограничения» → руководители (слева) и вызов цехов + база в две колонки (справа) → актёры → групповка и элементы площадки одной таблицей с разделами.
  - **Лист 2:** план съёмки (служебные строки — тонкие серые полосы, элементы сцены — одной строкой «Раздел: …» под синопсисом) → второй юнит → схема объекта (точки и тексты; нет данных — блока нет).
- Уплотнение:
  - строки одного раздела элементов с одинаковыми сценами и временами склеиваются через « · »;
  - вызов цехов и база — две колонки, по времени;
  - длинные должности — по «короткому названию».
- **Оформление блоков** (решение владельца: в образце блоки сливаются, читать трудно; образец задаёт состав и плотность, но не это). Цель — человек на площадке за 2–3 секунды находит свой блок на распечатанном листе.
  - **Шапка каждого блока — тёмная полоса на всю ширину блока** (почти чёрный фон, белый текст, жирный, капсом, ~11 px, высота ~18 px). Это главный разделитель. Цвет не нужен: лист печатают на ч/б принтере, полоса должна читаться и в сером.
  - **Между блоками — заметный отступ** (6–8 px), внутри блока — прежняя плотность. Блок — рамка 1 px вокруг всего блока (шапка + таблица), чтобы при двух колонках было видно, где кончается левый и начинается правый.
  - **Разделы внутри таблицы** (игровой транспорт, реквизит… в элементах площадки; второй юнит в плане) — светло-серая полоса с жирным названием раздела, не путать с шапкой блока.
  - **Строки таблиц** — чередование белый / очень светло-серый (зебра), чтобы глаз не терял строку по горизонтали. Служебные строки плана — как и было, тонкие серые полосы, но отличимые от зебры (курсив или меньший кегль).
  - **Главное — крупно:** сбор (время и место), начало смены, мотор, обед — в шапке крупнее остального (время сбора — самое крупное на листе). Номер сцены в плане — жирный и крупнее текста строки.
  - **«Важно»** — плашка с толстой чёрной полосой слева (4 px) и светлым фоном, первым блоком после шапки. Пусто — плашки нет.
  - Все цвета — оттенки серого, контраст текста к фону ≥ 4.5:1, ничего не держится на цвете. Шрифты и размеры таблиц — прежние (11,5 px).
  - **Компактность не жертвуется:** обычный день остаётся на 2 листах A4. Если разделение съедает место — сначала уменьшать отступы внутри блоков, не убирать шапки блоков. Не влезает — покажи мне, что выбрать.
  - **Сначала согласование:** до вёрстки всех блоков сделай лист 1 обычного дня в новом оформлении, скриншот просмотра (и печатного вида, если получится) — стоп, жди «дальше». Потом остальное.
- Тяжёлый день: что не влезло на лист 1, переезжает на лист 2 перед планом. Шапка таблицы повторяется на новой странице, строка сцены не разрывается.
- Подвал каждой страницы: проект, дата, смена, статус и время утверждения, «лист N из M» (через CSS-счётчики страниц, если браузер их печатает; если нет — скажи, что получится).
- Кнопка «Печать / PDF»: печатный HTML собирается на сервере, окно печати — как в пробах и кастинге (`printWhenImagesSettled`).
- Excel: листы Сводка, Люди и элементы, План, Схема (точки текстом). ExcelJS, `excelSafe`, отдача маршрутом.

## Шаг 4. Экран правки и статусы

- Экран вызывного на всю ширину, вкладки «Правка» и «Просмотр». Просмотр — тот же шаблон, что печать.
- Правка по блокам, в порядке листов. Блоки сворачиваются.
- **Блоки правки визуально разделены** так же явно, как на листе: каждый блок — отдельная карточка с заметной шапкой (название блока, счётчик строк, кнопка свернуть), отступ между карточками. Цвета — CSS-переменные темы, светлая и тёмная. В свёрнутом блоке видно, заполнен ли он (например, «Актёры · 4» или «пусто»).
- Статусы: черновик → на согласовании → утверждён. Утверждение увеличивает номер версии. Правка утверждённого — новый черновик следующей версии. Время утверждения — в подвале.
- Утверждение — по номеру правки, как у сметы: сервер под блокировкой сверяет правку, которую видел утверждающий. Изменили после того, как он открыл, — отказ с понятным текстом. Перед утверждением — подтверждение.
- Две вкладки — конфликт по номеру правки, как у сметы: вторая вкладка не перетирает первую, плашка «Изменили в другом окне — обновите».
- Права: правит роль с правом на вызывные; утверждает — флаг матрицы «Вызывные — утверждение». Предложи, кому включить миграцией.
- Несохранённые изменения — общий механизм с «Сохранить».
- Аудит: создание, правки, смена статуса, выгрузки.

## Шаг 5. Google Диск

Сначала план и вопросы, жди «дальше».

**Диски**
- Диск проекта: подключает владелец проекта (волна 2в) или продюсер — предложи. Файлы создаются от имени подключившего. Что происходит при передаче владения и при удалении подключившего из проекта — предложи (диск отключается / остаётся с предупреждением).
- Личные диски: каждый с правом по роли может подключить свой. При отправке выбирается, куда.
- Права у Google — минимальные: `drive.file`. Если сейчас запрашивается больше — уменьшить и сказать мне, что проверить в Google Cloud Console.

**Папки**
- Структура на диске проекта: `<Проект>/Общая`, `<Проект>/Продюсеры`, `<Проект>/Цеха/<Цех>`.
- Человек выбирает папку из доступных ему. По умолчанию: вызывные — «Общая», сметы цеха — папка цеха, сводная книга — «Продюсеры».
- Доступ выдаёт система по почтам («Почта для Google», иначе почта входа):
  - «Общая» — все активные участники;
  - «Продюсеры» — продюсеры и роли с «Сметы — просмотр всех»;
  - папка цеха — главы цеха, продюсеры и «Сметы — просмотр всех». Других не добавлять: там ставки людей.
- Роль в Google — «комментатор».
- Доступ «по ссылке для всех» — только для «Общей», отдельной галочкой с предупреждением: «Ссылку могут переслать, в вызывном телефоны людей». Для «Продюсеров» и цехов — недоступно.
- Пересчёт доступов: смена роли, назначение и снятие главы цеха, удаление из проекта, флаг «Сметы — просмотр всех» у роли (все участники с ней), смена «Почты для Google», передача владения (если влияет). Храни, какие доступы выдала система, трогай только их.
- Ошибка Google при пересчёте не ломает действие в системе. Неудача — в журнал и в список «доступы не синхронизированы» с «Повторить» у продюсера.
- Если диск проекта — «Общий диск» Google Workspace, предупредить: его участники видят всё, разграничение по папкам не работает.

**Отправка и обновление**
- «Отправить на диск»: формат — **Google Таблица** (из Excel вызывного). Диск, папка. Результат — ссылка, которую можно скопировать. PDF на диск — после переезда; код отправки делай так, чтобы второй формат добавлялся без переделки.
- Повторная отправка обновляет **тот же файл** (тот же id, ссылка та же). В имени — дата и номер версии.
- Храни связь «вызывной → файл, папка, формат, кто, когда».
- Файл уходит в Google с сервера, не через браузер.

**Яндекс Диск**
- Проверь по документации, можно ли через API дать доступ конкретным людям. Если только публичная ссылка — в Яндекс только «Общая» по ссылке, с тем же предупреждением; «Продюсеры» и цеха недоступны, в интерфейсе одна строка объяснения.

Аудит: подключение и отключение дисков, отправка, обновление, выдача и снятие доступов (без почт и телефонов в `changes`). Типы записей — в карту `entity-access.ts`.
