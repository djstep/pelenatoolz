## Что получится

- Вызывной в своём формате, компактно — на обычный день 2 листа A4. Лист 1: шапка, погода, объекты, «важно», руководители, вызов цехов, база, актёры, групповка и элементы. Лист 2: план съёмки, второй юнит, схема объекта. Образец — `docs/tasks/ref/callsheet/callsheet-mockup.pdf`.

- Предпросмотр, PDF и файл на диске собираются из одного шаблона: что видишь, то и уходит команде.

- Статусы: черновик → на согласовании → утверждён, с номером версии.
- Отправка на Google Диск: выбор диска (диск проекта или личный) и папки (общая папка проекта или папка цеха). Повторная отправка обновляет тот же файл, ссылка не меняется. Команда получает права «комментатор», правок в Google нет.

## Шаг 1. Шаблоны проекта

В настройках проекта раздел «Шаблон вызывного»:
- **Руководители группы**: строки «должность · человек · телефон». Человек — участник проекта (тогда ФИ и телефон берутся из профиля) или свободный текст, если человека нет в системе. Порядок перетаскиванием.
- **Цеха и вызов**: строки «цех · время вызова по умолчанию». Цех — из сущности цехов волны 2 или свободная строка (каскадёры, рабочие и т.п.).
- **База и транспорт группы**: строки «наименование · время по умолчанию · не нужен».
- Новый вызывной получает **копию** шаблона (снимок, правки в вызывном шаблон не меняют). Кнопка «Обновить из шаблона» в вызывном — с подтверждением, что ручные правки этих блоков перезапишутся.
- У профиля пользователя проверь наличие телефона. Если нет — добавь поле. Плюс поле «Почта для Google» (может отличаться от почты входа) — понадобится в шаге 5.
- Телефоны — персональные данные: в аудит их не писать.

## Шаг 2. Все поля вызывного

Полный состав. Что можно — подтягивается автоматически и правится руками.

**Шапка и день**
- проект, дата (день недели — сам), номер смены, «день N из M» (если есть в КПП), версия вызывного;
- количество сцен и хронометраж дня — считаются по плану съёмки;
- сбор группы: время и место (адрес) крупно;
- времена: начало и конец смены, репетиция, мотор, обед (с–по), стоп-мотор;
- погода: описание, t днём, t ночью — руками (позже можно подключить источник); восход и закат — сами, по координатам объекта (в проекте уже есть расчёт солнца);
- объекты дня: адрес, список подобъектов с номерами сцен (сам из плана), отметка второго юнита;
- «Ограничения по актёрам» — текст;
- «Важно» — текст, выделенная плашка (если пусто — плашки нет).

**Люди**
- руководители группы — из шаблона;
- вызов цехов — из шаблона, сортировка по времени;
- база и транспорт группы — из шаблона, сортировка по времени, «не нужен»;
- актёры: персонаж, актёр, сцены (сами из плана), транспорт («машина за актёром» / «сам» / свой текст), прибытие, костюм, грим, готовность, конец смены;
- групповка и дублёры: кто, кол-во, сцены, прибытие, готовность, конец.

**Элементы площадки** — одна таблица с разделами: игровой транспорт, реквизит, костюм, трюки, операторская техника, CG, спецтранспорт. Список разделов расширяемый. Колонки: что, сцены, прибытие, готовность, конец. Элементы подтягиваются из разбора сцен дня (если в либретто они размечены), добавляются руками.

**План съёмки**
- строки двух типов: «сцена» и «служебная» (грим/освоение, репетиция, подготовка, обед, переезд, продолжение сцены N, свой текст);
- у строки: начало, длительность (конец считается), для сцены — номер, ИНТ/НАТ, объект, режим и день по сценарию, синопсис, персонажи, хронометраж — всё из либретто; элементы сцены по разделам; примечание;
- второй юнит — отдельная дорожка со своими строками;
- итого хронометража по основному юниту.

**Схема объекта**
- у объекта (локации) поле «схема»: загруженная картинка (через закрытое хранилище проекта, как остальные файлы);
- точки: номер, название, описание (проходная/сбор, караван, площадка…);
- «как добраться», «парковка», «на месте» — текст.

## Шаг 3. Шаблон вывода: просмотр, PDF, Excel

- Один шаблон → три выхода: просмотр в системе, PDF, Excel. Вид — по образцу `docs/tasks/ref/callsheet/`.
- Шрифт IBM Plex Sans, подключённый из проекта (не с Google Fonts — сервер генерации может не иметь интернета). Цифры — тем же шрифтом с `font-variant-numeric: tabular-nums`. Моноширинный шрифт не использовать.
- Главное требование — компактность: обычный день (как в образце) должен укладываться в 2 листа A4. Шрифт таблиц 11,5 px, строки ~19 px, как в образце. Не раздувать отступы.
- Порядок блоков:
  - **Лист 1:** шапка (проект, дата, смена, хронометраж + блок времён + крупно сбор и место) → строка «погода · объекты · важно/ограничения» → руководители группы (слева) и вызов цехов + база и транспорт в две колонки (справа) → актёры → групповка и элементы площадки одной таблицей с разделами.
  - **Лист 2:** план съёмки (служебные строки — тонкие серые полосы, элементы сцены — одной строкой «Раздел: …» под синопсисом) → второй юнит → схема объекта (карта слева, точки и «как добраться» справа). Нет схемы и точек — блока нет.
- Правила уплотнения:
  - в элементах площадки строки одного раздела с одинаковыми сценами и временами склеиваются в одну через « · »;
  - вызов цехов и база — в две колонки, отсортированы по времени;
  - длинные должности сокращаются по словарю шаблона (поле «короткое название» у строки шаблона).
- Тяжёлый день: что не влезло на лист 1, переезжает на лист 2 перед планом, план — дальше. Шапка таблицы повторяется на новой странице, строка сцены не разрывается.
- Подвал каждой страницы: проект, дата, смена, статус и время утверждения, «лист N из M».
- Excel: те же блоки по листам книги (Сводка, Люди и элементы, План, Схема — без картинки, точки текстом), ExcelJS на сервере, защита от формул в ячейках.
- Старый предпросмотр и выгрузки в стиле FilmToolz удалить.
- Проверь вывод на двух днях: обычный (как в образце) и тяжёлый (10+ сцен, 8 актёров, 20 элементов). Покажи мне PDF обоих.

## Шаг 4. Экран правки и статусы

- Экран вызывного на всю ширину, вкладки «Правка» и «Просмотр». Просмотр — тот же шаблон, что PDF.
- Правка по блокам, в порядке листов. Блоки сворачиваются.
- Статусы: черновик → на согласовании → утверждён. Утверждение увеличивает номер версии. Правка утверждённого — новый черновик следующей версии. Время утверждения — в подвале.
- Права: правит роль с правом на вызывные; утверждает — 2-й режиссёр / продюсер (через флаг матрицы прав «Вызывные — утверждение», предложи).
- Предупреждение о несохранённых изменениях — из волны 1.
- Аудит: создание, правки, смена статуса, выгрузки.

## Шаг 5. Google Диск

Сначала покажи мне план и жди «дальше».

**Диски**
- Диск проекта: продюсер подключает свой Google Диск как диск проекта. Файлы создаются от его имени.
- Личные диски: каждый с правом по роли может подключить свой. При отправке выбирается, куда.
- Права у Google — минимальные: только файлы, созданные приложением (`drive.file`). Если сейчас запрашивается больше — уменьшить и сказать мне, что проверить в Google Cloud Console.

**Папки**
- Система создаёт на диске проекта структуру: `<Проект>/Общая`, `<Проект>/Цеха/<Цех>` для каждого цеха.
- При отправке человек выбирает «Общая папка проекта» или «Папка цеха <X>» (только цеха, к которым у него есть доступ). Вызывные по умолчанию — общая, сметы — папка цеха.
- Доступ к папкам выдаёт система, по почтам («Почта для Google» из профиля, иначе почта входа):
  - общая — все участники проекта;
  - папка цеха — главы и участники цеха, продюсеры, флаг «Сметы — просмотр всех».
- Роль в Google — «комментатор». Править в Google нельзя.
- Доступ «по ссылке для всех» — только для файлов из общей папки, по отдельной галочке с предупреждением: «ссылку могут переслать, в вызывном телефоны людей». Для папок цехов недоступно.
- Сменили человеку роль или цех в системе, удалили из проекта — система пересчитывает его доступ на диске (снимает или выдаёт). Храни, какие доступы выдала система, и трогай только их.
- Если диск проекта — «Общий диск» Google Workspace, предупредить: его участники видят всё, разграничение по цехам не работает.

**Отправка и обновление**
- Кнопка «Отправить на диск»: формат (PDF или Google Таблица из Excel), диск, папка. Результат — ссылка, которую можно скопировать.
- Повторная отправка того же вызывного обновляет **тот же файл** (тот же id, ссылка не меняется). Новая версия — новое содержимое. В имени файла — дата и номер версии.
- Храни связь «вызывной → файл на диске, папка, формат, кто отправил, когда».

**Яндекс Диск**
- Насколько известно, через API Яндекс Диска нельзя дать доступ конкретным людям, только публичную ссылку. Проверь по документации. Если это так — в Яндекс можно отправлять только в общую папку и только по ссылке, с тем же предупреждением; папки цехов для Яндекса недоступны, и в интерфейсе это объяснено одной строкой.

Аудит: подключение и отключение дисков, отправка, обновление, выдача и снятие доступов (без почт и телефонов в `changes`).
