## Мои предложения по объединению (Claude Code сверит с реальным меню)

Принцип: один пункт меню = одна задача пользователя. Вкладки — когда человек постоянно ходит между экранами туда-обратно.

| Новый пункт | Вкладки | Почему |
|---|---|---|
| Кастинг | Кандидаты · Пробы | Одна воронка, ходят туда-обратно постоянно — твоё решение |
| Локации | Утверждённые · Скаут | Та же воронка: кандидат → утверждённый объект |
| Персонажи и актёры | Персонажи · Актёры · Занятость | Занятость — свойство актёра, отдельный пункт меню лишний |
| Сценарий | Текст · Версии и сравнение · Импорт | Если сейчас это разные пункты меню |
| Съёмочный день | Вызывные · Отчёты смены · Явочные листы | Всё про конкретный день; только если сейчас 3 отдельных пункта |
| Деньги | Начисления · Платежи · Операции | Один поток денег |
| Контрагенты | Контрагенты · Договоры · Акты | Договоры и акты всегда от контрагента |
| Отчёты (финансы) | План/факт · Сводная · Ведомость · Отчёты | Всё, что только читается |
| Настройки | Проект · Участники и роли · Цеха · Ресурсы · Словарь · Финансы · Журнал | Всё редкое — в одно место |

Чего **не** объединять: Смету (полноэкранная, своя навигация), КПП (рабочий экран на весь день), Либретто (основной рабочий список). Им нужен свой пункт.

## Правила волны

- **Адреса страниц не меняются.** Объединение делается общей разметкой с полосой вкладок над существующими страницами: группы маршрутов Next.js (`(группа)/layout.tsx`) или общий `layout.tsx`, если страницы уже вложены. Каждая вкладка — существующая `page.tsx` со своей загрузкой данных, без изменений. Если без смены адреса никак — покажи, предложи переадресацию со старого адреса, жди «да».
- Вкладка = ссылка (`<Link>`), активная определяется по адресу. «Назад» в браузере, прямые ссылки, открытие в новой вкладке — работают.
- Права: вкладка видна, только если у пользователя есть право на эту страницу (та же проверка, что сейчас у пункта меню, — `filterNavGroups` или аналог). Пункт меню виден, если видна хотя бы одна вкладка, и ведёт на первую доступную. Прямой заход на недоступную вкладку — как сейчас на недоступную страницу.
- Несохранённые изменения при переходе по вкладке — существующий механизм предупреждения должен срабатывать (проверь, что он ловит переход по `<Link>`).
- Оформление вкладок — компонент сегментов/вкладок из волны 5, один на всю систему. Счётчики во вкладках — только если число уже есть в данных, новых запросов не делать.
- Внутри экранов ничего не меняется: функции, тексты, поля, кнопки. Заголовок страницы может уйти в общий заголовок раздела над вкладками — только если иначе он дублируется; спроси.
- Сохранение раскрытых разделов меню в `localStorage` (`filmprod-nav-sections`) — старые ключи не должны ломать меню (неизвестный ключ игнорируется).
- Миграций нет. Новые пакеты не нужны.

## Шаг 1. Механизм вкладок + Кастинг

- Общий компонент раздела с вкладками: заголовок раздела, полоса вкладок, содержимое. Описание вкладок — данными (название, адрес, проверка прав), рядом с описанием меню, чтобы меню и вкладки брали права из одного места.
- Кастинг: Кандидаты · Пробы. Пункт меню «Кастинг», вкладки на существующих страницах.
- Проверка: e2e кастинга и проб зелёные; новый e2e — переход по вкладкам, «Назад», прямая ссылка на пробы, аккаунт без прав на одну из вкладок (если такая комбинация прав возможна).

## Шаг 2. Словарь и остальные объединения

- Словарь сценария — пункт или вкладка в «Настройках» (как утверждено), адрес тот же. Со страницы сценария — ссылка на словарь там, где сейчас к нему есть переход (если есть), не удалять.
- Остальные строки таблицы — только утверждённые, по одной строке — отдельный коммит.
- Проверка после каждой строки: e2e зелёные, скриншот меню продюсера и аккаунта без финансов.
