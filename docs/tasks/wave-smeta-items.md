## Общие правила
- Прод на своём VPS (https://pelena.space). Базы dev и e2e — локальный PostgreSQL. Миграции на прод вручную не применять — они уходят через sudo pelena-deploy после моего слияния в main.
- Reviewer — на шагах 2 (модель, миграция) и 4 (расчёты, права), и один раз в конце волны.
- Изменения данных — через auditMutation.
- Права — через существующую систему ролей (волны 2б, 2в): глава цеха правит смету своего цеха; продюсер утверждает, видит все сметы, ведёт шаблон статей и сводную; роль с «просмотром всех» только читает. Переменные, типы расходов, формы оплаты меняют продюсер и роль с «Финансы: правка»; главы цехов их только видят.
- Нынешние статьи сметы, на которые ссылаются начисления, платежи, статьи по умолчанию у актёров и ресурсов, отчёт смены и план/факт, становятся строками новой сметы с теми же id. Эти связи не рвать. Если так нельзя — стоп, спроси.
- Коды статей/подстатей/строк (вида TR-05.02.03) — внутренние: пользователю на экране не показывать нигде (смета цеха, сводная, версии, сравнение, начисления/платежи — где раньше был код статьи, показывать название). В выгрузке Excel — отдельная колонка «Код» (нужна для импорта обратно), её можно скрыть в конструкторе колонок.
- Деньги — Decimal, округление до копеек на уровне строки, итоги — сумма округлённых строк.
- Оформление — компоненты и правила волны 5. Таблица сметы — по правилам таблиц волны 5, числа выровнены вправо, тысячи разделены.
- Новые пакеты — только после моего «да».
- Термин везде — «Налог». НДС в системе нет: налог — это налог на доход исполнителя (например, 6% у ИП).
- В этой папке параллельно других сессий нет; ветки других задач не трогать. Не пушить и не сливать в main.

## Принятые решения
1. Общий шаблон статей на фильм; глава цеха добавляет только подстатьи и строки, новые статьи — продюсер в шаблоне.
2. Номер статьи в цехе = номер статьи в шаблоне (одна статья — один номер во всех цехах). Внутренний код с префиксом цеха, два уровня над строкой; на экране не показывается.
3. Типы расходов: гонорар/ФОТ, аренда техники, покупка/расходники, транспорт, услуги подрядчика, площадки, питание, проживание, суточные, прочее. Налог от типа не зависит.
4. Множители: СМЕНЫ, СЕРИИ, ДНИ ПОДГОТОВКИ, НЕДЕЛИ и свои переменные; до трёх на строку; вместо переменной — своё число. Новые переменные по умолчанию пустые.
5. Налог — по форме оплаты строки (самозанятый, ИП, ГПХ, наличные, юрлицо — набор правится). У формы процент по умолчанию, в строке можно поменять.
6. Резерв и агентские — только в сводной продюсера, % от суммы с налогом, действуют всегда, смена процента — в журнал.
7. Переменные меняют продюсер и финансы, главы цехов только видят. После утверждения утверждённая версия не меняется; черновик пересчитывается и получает пометку «изменилась после утверждения».
8. Черновики Excel остаются рядом со сметой; есть импорт из Excel в статьи.
9. Перенос старых смет не делается. Старый табличный редактор убирается. Утверждённые версии в старом формате — только чтение.
10. В договоре и акте налог по умолчанию — из формы оплаты, сопоставленной типу контрагента; не сопоставилось — пусто.

## Шаг 2. Модель и миграция
- Шаблон статей фильма: номер, название, порядок, архив. Номер не переиспользуется.
- Статья цеха: ссылка на статью шаблона, смета цеха.
- Подстатья: номер внутри статьи, название, порядок, архив.
- Строка (нынешняя статья с прежним id): подстатья, номер внутри подстатьи, наименование, тип расхода, единица, количество, ставка, до трёх множителей (каждый — переменная проекта или своё число), форма оплаты, налог % (копия из формы, правится), архив. Внутренний код строки собирается из префикса цеха и номеров уровней, номера не переиспользуются.
- Справочники проекта: типы расходов, формы оплаты с процентом по умолчанию, сопоставление «тип контрагента → форма оплаты».
- Переменные: добавить «ДНИ ПОДГОТОВКИ» и «НЕДЕЛИ», значения по умолчанию пустые.
- Сводная: проценты резерва и агентских на проект.
- Версия сметы: снимок новой структуры (уровни, строки, значения переменных на момент утверждения). Старые версии табличного формата — только чтение.
- Начальные справочники — миграцией в существующие проекты и при создании проекта; открытие страницы ничего в базу не пишет.
- Тестовые сметы старого формата не переносить — пересоздать в сиде на шаге 9.

## Шаг 4. Расчёты и действия на сервере
- Строка: сумма = количество × ставка × множители; налог = сумма × налог %; итого = сумма + налог. Пустая переменная-множитель = строка без суммы с пометкой «не задана переменная», не ноль молча.
- Итоги подстатьи, статьи, сметы цеха.
- Действия: взять статью из шаблона, добавить подстатью, добавить строку, изменить, переместить внутри уровня, убрать в архив, вернуть. Всё через права и журнал.
- Юнит-тесты расчётов, включая округление и пустые переменные.

## Шаг 5. Экран сметы цеха
- Таблица-дерево: статья → подстатья → строки, сворачивание уровней (запоминается), итоги на каждом уровне и общий. Кодов на экране нет.
- Ввод в строке: наименование, тип, единица, количество, ставка, множители (переменная или число), форма оплаты (налог % подставляется, можно поменять).
- Вкладка «Черновики» с листами Excel (существующий механизм).
- Старый табличный редактор убрать. Старые утверждённые версии — просмотр только чтение.
- Несохранённые изменения — существующий механизм.

## Шаг 6. Утверждение и версии
- Отправка, утверждение, возврат — на новой модели, как сейчас по смыслу.
- Просмотр версии, сравнение двух версий (что добавлено, удалено, изменено по суммам).
- Смена переменной после утверждения: утверждённая версия не меняется, черновик пересчитывается и получает пометку «изменилась после утверждения» с перечнем переменных.

## Шаг 7. Сводная продюсера и план/факт
- Сводная из новых смет цехов: по цехам и по статьям шаблона (одинаковые статьи складываются).
- Сводная по статьям шаблона раскрывается до цехов, подстатей и строк (например, «Транспорт» → цеха → «Камерваген», «Гримваген», «Тонваген»), с итогами на каждом уровне. Свёрнутость уровней запоминается.
- Резерв и агентские — % от суммы с налогом, отдельными строками, входят в план; смена процента — в журнал.
- План/факт работает от строк новой сметы (те же id, что у прежних статей).

## Шаг 8. Excel и Диск
