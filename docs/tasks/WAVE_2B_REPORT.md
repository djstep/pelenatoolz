### Задача 2. Окна стирают введённое после отказа сервера

**Причина.** Не сброс по ответу сервера: React 19 после отправки через `<form action={…}>` сам возвращает поля без состояния к исходным — и при отказе тоже. Если форма отменяет отправку сама и запускает действие через `startTransition`, React поля не трогает.

**Сделано.** `src/shared/ui/forms/submit-keeping-fields.ts` — обработчик `onSubmit` (`preventDefault` → `FormData` с кнопкой-отправителем → `startTransition`). В 21 форме окон `action={action}` заменено на него, больше ничего не менялось. Блокировка кнопки на время запроса осталась (двойной клик — один запрос).

**Окна — проверены и исправлены** (21 форма, 20 файлов): роль; начисление; новый кандидат кастинга; персонаж; акт / справка; договор; компания и контрагент; цех; статус согласования; своя переменная финансов; операция финансов; локация; платёж наличными; задача поста; удаление проекта; категория и позиция ресурсов; правка и новый кандидат скаута; новая сцена. Окна, где поля хранятся в состоянии и сохраняются без формы (факт сцены, доплаты в отчёте смены, перенумерация либретто, слот проб), — правка не нужна.

Три семьи: (1) сценарий, сцены, роль — `export-screenplay.ts`, `export-scene-script.ts` (роль — через него), letter, Courier New, поля 1 / 1 / 1 / 1,5 дюйма; (2) таблицы — пробы (`export-schedule.ts`), каст-лист (`export-cast-list.ts`), `system-ui`, без `@page`; (3) вызывной (`export-call-sheet.ts`), A4, Arial.
