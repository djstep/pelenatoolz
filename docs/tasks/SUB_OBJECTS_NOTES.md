# Объекты и подобъекты (feat/sub-objects) — заметки волны

Задача: объект (ДОМ) → подобъекты (КУХНЯ, КОРИДОР…), сцена привязана к одному объекту и одному или нескольким
подобъектам (смежные сцены). Как в FilmToolz. На проде живой проект — только миграцией поверх данных.

## Решения владельца (10.11.2026)
1. Реальное место (адрес, координаты, схема, утверждённый скаут) — внутри объекта и подобъекта. Подобъект без своего
   адреса берёт место объекта целиком. Справочник «Площадки» — позже, в бэклоге.
2. Аренда в отчёте смены — одна строка на реальное место в день, не на каждый подобъект.
3. Сцена с двумя разными объектами (сц. 9: НАТ. ДВОР ДОМА / ОПУШКА ЛЕСА) — остаётся как есть, с пометкой.
4. Тип ИНТ/НАТ/ПАВ у подобъекта свой, по умолчанию берётся от объекта.
5. План из 8 шагов — ок.

## Модель
- `Location.parentId` (ссылка на ту же таблицу; объект с подобъектами удалить нельзя) и `Location.sortOrder`.
- Объект: `parentId` пусто. Подобъект: `parentId` = объект, `name` = имя подобъекта.
- `sublocation` до шага 2 хранит подобъект по-старому, после шага 2 пусто, в шаге 8 поле убирается.
- Сцена: та же таблица `SceneLocation`. Привязка к строке объекта — «объект без подобъекта», к строкам подобъектов — смежные.
  Все id строк сохраняются: сцены, отчёты, скаут, вызывные, словарь, календарь, фото, точки, ставки не перепривязываются.

## Шаги
1. Поле в базе (`parentId`, `sortOrder`, без переноса данных) и общие подписи «объект + подобъект» во всех местах; внешне ничего не меняется.
2. Разбивка данных (миграция по таблице выше), импорт и редактор сценария пишут новую форму. Reviewer.
3. Экран «Объекты»: дерево, переименовать, переставить.
4. Объединение объектов и подобъектов со всеми связями. Reviewer.
5. Карточка сцены: объект + несколько подобъектов (заодно ошибка: сохранение карточки стирало все привязки, кроме первой); колонка либретто.
6. Своё место у подобъекта: скаут, вызывной, аренда в отчёте (одна строка на место). Reviewer.
7. КПП (группировка, фильтр, подобъекты дня), вызывной, экспорты.
8. Убрать `sublocation`, тесты, отчёт волны, итоговая проверка, `e2e:drive`.

## Перенесено на следующие шаги (замечания reviewer к шагу 1)
- Шаг 2, до выкатки переноса: сортировка списков объектов `orderBy: [{ name }, { sublocation }]` (`script/queries.ts`
  listLocations, `scout/queries.ts`, `preproduction/scout/page.tsx`, `prep-calendar/queries.ts`, `locations/queries.ts`) —
  после переноса подобъекты разойдутся по алфавиту; сортировать по объекту, затем по подобъекту.
- Шаг 2: «применить адрес к соседним» (`locations/actions.ts`, создание и правка) ищет соседей по `name` — после переноса
  перейти на `parentId`.
- Шаг 2: подписи правил словаря в вопросах импорта (`import/review/question-text.ts`) — с объектом.
- Шаг 2: в базе запретить ссылку на себя (`CHECK ("parentId" <> id)`); родитель того же проекта и один уровень вложенности —
  проверкой в коде (`assertInProject`) или составным ключом `(parentId, projectId)`.
- Шаги 3–4: удаление объекта с подобъектами — понятный отказ до удаления (сейчас ошибка базы); журнал создания и удаления —
  с полной подписью; `quickCreateLocationAction` пишет в журнал (сейчас нет, старое).
- Шаг 6: сообщение об утверждении скаута — с подобъектами («ДОМ, ДОМ» → «ДОМ.КУХНЯ, ДОМ.КОРИДОР»).
- Шаги 5 и 7: `syncSluglineFromScene` пишет в шапку только объект, подобъект теряется (было и раньше).
- Шаг 5: быстрое создание объекта по названию раньше могло вернуть строку «ДОМ.КУХНЯ» на ввод «ДОМ» (старое).
