# Объекты и подобъекты (feat/sub-objects) — заметки волны

Задача: объект (ДОМ) → подобъекты (КУХНЯ, КОРИДОР…), сцена привязана к одному объекту и одному или нескольким
подобъектам (смежные сцены). Как в FilmToolz. На проде живой проект — только миграцией поверх данных.

## Решения владельца (10.11.2026)
1. Реальное место (адрес, координаты, схема, утверждённый скаут) — внутри объекта и подобъекта. Подобъект без своего
   адреса берёт место объекта целиком. Справочник «Площадки» — позже, в бэклоге.
2. Аренда в отчёте смены — одна строка на реальное место в день, не на каждый подобъект.
3. Сцена с двумя разными объектами (сц. 9: НАТ. ДВОР ДОМА / ОПУШКА ЛЕСА) — остаётся как есть, с пометкой.
4. Тип ИНТ/НАТ/ПАВ у подобъекта свой, по умолчанию берётся от объекта.
5. План из 8 шагов — ок.

## Модель
- `Location.parentId` (ссылка на ту же таблицу; объект с подобъектами удалить нельзя) и `Location.sortOrder`.
- Объект: `parentId` пусто. Подобъект: `parentId` = объект, `name` = имя подобъекта.
- `sublocation` до шага 2 хранит подобъект по-старому, после шага 2 пусто, в шаге 8 поле убирается.
- Сцена: та же таблица `SceneLocation`. Привязка к строке объекта — «объект без подобъекта», к строкам подобъектов — смежные.
  Все id строк сохраняются: сцены, отчёты, скаут, вызывные, словарь, календарь, фото, точки, ставки не перепривязываются.

## Шаги
1. Поле в базе (`parentId`, `sortOrder`, без переноса данных) и общие подписи «объект + подобъект» во всех местах; внешне ничего не меняется.
2. Разбивка данных (миграция по таблице выше), импорт и редактор сценария пишут новую форму. Reviewer.
3. Экран «Объекты»: дерево, переименовать, переставить.
4. Объединение объектов и подобъектов со всеми связями. Reviewer.
5. Карточка сцены: объект + несколько подобъектов (заодно ошибка: сохранение карточки стирало все привязки, кроме первой); колонка либретто.
6. Своё место у подобъекта: скаут, вызывной, аренда в отчёте (одна строка на место). Reviewer.
7. КПП (группировка, фильтр, подобъекты дня), вызывной, экспорты.
8. Убрать `sublocation`, тесты, отчёт волны, итоговая проверка, `e2e:drive`.

## Шаг 2 — сделано
- Миграция `20261110150000_location_split_sub`: перенос по таблице выше; родитель только из того же проекта (составной ключ),
  ссылка на себя запрещена (CHECK). Пробный прогон на dev в транзакции с откатом, повтор ничего не меняет.
- Импорт видит объекты парой (`locationAsPair`), новые подобъекты пишет под объектом (объект — раньше).
- Окно «Локации»: подлокация → подобъект объекта «Название»; «применить адрес к соседним» — по `parentId`; объект с
  подобъектами не удаляется (понятный отказ); правка, создание и попутно созданный объект — в журнале.
- Шапка в редакторе сценария (`quickCreatePlaceAction`) раскладывает место на объект и подобъекты, как импорт.
- Поиск объекта по названию — как у импорта (регистр, пробелы, Ё = Е), с блокировкой от двойного создания.
- Порядок во всех списках объектов — `compareLocations` (объект, затем его подобъекты по порядку).

## Шаг 3 — сделано
- Экран «Локации» переименован в «Объекты» (меню, заголовок, вкладки «Объекты · Скаут», подписи экрана, окно, e2e).
  Адреса страниц прежние (`/locations`). Подписи в журнале изменений («Создана локация …») не менялись.
- Дерево: объект, под ним подобъекты по порядку; свернуть/развернуть; найденный подобъект — вместе со своим объектом.
- Действия строки — в меню «⋯» (добавить подобъект, изменить, удалить); у подобъектов на виду стрелки ↑↓.
  На 1280 px таблица без прокрутки вбок (проверка в e2e `c34`).
- Объекты — по алфавиту, ручной перестановки объектов нет (решение владельца). Тип нового подобъекта — от объекта.

## Шаг 4 — сделано
- «⋯ → Объединить с…» на экране «Объекты»: объект с объектом, подобъект с подобъектом (в том числе другого объекта).
  Объединяемый исчезает; к оставшемуся переходят сцены, скаут, схема вызывного, строки отчётов смены (с ключом
  `location:<id>` — «Обновить из КПП» их узнаёт), правила словаря (и ответ «к какой записи»), события календаря, фото,
  точки схемы, ставки переработки; у объекта — подобъекты, одноимённые сливаются. Поля оставшегося не меняются,
  пустые заполняются из объединяемого. Окно заранее показывает, что произойдёт.
- Отказы: разный вид; финансовые условия (в том числе стоимость скаута) без права на финансы объектов; оба в одном
  отчёте смены; разные статьи сметы при строках отчётов у объединяемого.
- Код: `locations/lib/location-merge.ts`, `mergeLocationsAction`, `getLocationMergeImpactAction`; e2e `c37`.
- Мелочи reviewer, не сделанные: номера точек схемы при объединении могут задвоиться («1», «1»); узкое окно гонки
  с одновременной привязкой сцены к объединяемому; после объединения подобъектов разных объектов сцена может оказаться
  с двумя объектами — окно об этом не предупреждает.

## Шаг 6 — сделано
- Своё место у подобъекта — если заполнен его адрес; иначе место объекта целиком (адрес, координаты, схема вызывного),
  поля не смешиваются (`hasOwnPlace`, `placeOf`). Так берут вызывной (группы адресов, схема), восход/закат, документы
  дня (явочный лист, время в пути), либретто («Место», фильтр по адресу).
- Аренда в отчёте смены — одна строка на реальное место в день (`rentOwner` в `sync-work-rows.ts`): подобъекты без
  своего адреса — строка объекта с его условиями. Если владелец места сменился, строка отчёта переходит на ключ нового
  владельца (`rekeyLocationRows`), а не удаляется — факт и начисления сохраняются.
- «Объекты»: у подобъекта без адреса — «<адрес> (как у объекта)», в карточке — «место как у объекта», подсказка в окне.
- Мелочи reviewer, не сделанные: свои финансовые условия и схема подобъекта без адреса не используются, а править их
  можно (есть подпись в карточке); фильтр по адресу и карта на экране «Объекты» — только по своему адресу; в ручных
  начислениях за смену подобъекты со своей статьёй видны отдельными строками; поля места у родителя в типах
  необязательные (сейчас все выборки их дают).
