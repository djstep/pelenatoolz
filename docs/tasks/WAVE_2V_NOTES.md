# Волна 2в — заметки по шагам (для итогового отчёта, шаг 7)

## Шаг 3. Фин. поля не уходят в браузер без фин. прав

Общий помощник: `src/shared/lib/finance-fields.ts` — `pickFinanceFields(row, { open, finance }, canFinance)`.
Явный список разрешённых полей: поле не из списка не уходит никогда; без права фин. полей в
ответе нет совсем (не `null`). Тот же помощник — для записи: присланные фин. значения без
фин. правки отбрасываются до записи.

| Место | Что вырезано без права | Право | Как проверено |
|---|---|---|---|
| Кастинг: список, карточка кандидата | ставка, условия; снимок утверждённого актёра в карточку кандидата не отдаётся никому. Телефон, почта, агент — остаются | чтение: фин. просмотр актёров; запись: фин. правка актёров | RSC/HTML под a@a.ru; прямой вызов `updateCastingPersonAction` (a@a.ru — отказ, Степа — сохранено) |
| Персонажи: список, страница, «Утверждённый актёр (снимок)» | ставка, условия, налог, длительности из снимка; сырой `castSnapshot` не уходит никому (список его не использует) | то же | RSC/HTML под a@a.ru; `updateCharacterCastSnapshotAction` |
| Карточка актёра (страница персонажа) | ставка, налог, режимы, переработки, доп. выплаты, статьи сметы, «особые условия» | фин. просмотр актёров | RSC/HTML под a@a.ru |
| Карточка объекта, список объектов | ставка, налог, режимы, переработки, статьи сметы; стоимость в снимке скаута | фин. просмотр объектов; запись стоимости — фин. правка объектов | RSC/HTML; `updateLocationScoutSnapshotAction` |
| Карточка ресурса, страница категории | ставка, налог, км, режимы, переработки, доп. выплаты, статьи сметы | фин. просмотр категории | RSC/HTML под a@a.ru |
| Отчёт смены: строки | ставки, налог, оплата, доп. выплаты, км-ставка, итоги; почасовые ставки строки не уходят никому. Часы, переработка, км — остаются | строка видна: право просмотра источника или `finance:read`; деньги — фин. просмотр источника (актёр / категория / объект; спецтранспорт — `finance:read`) | RSC/HTML под a@a.ru, Степа — всё видно |
| Отчёт смены: доп. выплаты | запись | фин. правка источника | `saveProductionWorkExtrasAction` |
| Отчёт смены: «устарел» / «Ставки отличаются» | «было → стало» и оплата — только имя строки | фин. просмотр источника | RSC под обоими аккаунтами |
| Отчёт смены: «Обновить ставки» | галочка и запись | фин. правка источников всех строк с расхождением | `refreshProductionReportAction` |
| Ведомость по использованию | пункт меню и страница | фин. просмотр хотя бы одного источника (`canReadAnyEntityFinance`); спецтранспорт в ней — `finance:read` | меню и страница под a@a.ru |

Решение по ведомости: в ней только суммы (смены, переработки, доплаты, км, итоги) — строк без денег
там нет. Сводная уже фильтровала строки по праву источника, поэтому для роли без фин. прав она была
пустой страницей. Пункт меню и страница теперь — только при фин. просмотре хотя бы одного источника.
Правило спецтранспорта в ведомости приведено к отчёту смены (было «прочие ресурсы», стало `finance:read`).

Правка факта (часы, Т/О, км) без фин. прав работает как раньше; оплату сервер пересчитывает сам.
Строку, которую пользователь не видит, он и не правит (`updateProductionWorkRowAction`).

## Шаг 5. «Фин. условия: редактирование» у «Финансов»

Флажок на деле давал только просмотр (`can(…, "finance", "finance")` = просмотр или правка; правка
модуля — `finance:write` — идёт от «Создания» / «Редактирования»). Теперь:
- сервер при сохранении роли превращает присланное «редактирование» в просмотр
  (`restrictSectionFlags` в `roles/permissions-matrix.ts`; у «Финансов» флажка `financeWrite` больше нет,
  `isSectionFlagAllowed`). То же при чтении роли из базы, поэтому права ролей не меняются;
- в окне роли в блоке «Финансы модуля» один флажок «Фин. условия: просмотр» и «Снятие фиксации
  платежей»; у ставок (актёры, локации, категории) «редактирование» осталось.

В базе ничего не чистилось: 4 роли с флажком («Продюсер» в трёх проектах, «ТЕСТ управление
участниками»), у всех стоит и просмотр. В базе флажок останется, пока роль не пересохранят.

Проверено: тесты (`permissions-matrix.test.ts`); окно новой роли под Степой — в блоке «Финансы модуля»
нет столбца «редактирование» (форма не сохранялась).

## Шаг 6. Вырезанные сцены

**Перенумерация** (`script/lib/scene-numbers.ts`, действия в `script/actions.ts`):
- право — `SCENE_NUMBERS_WRITE_PERMISSION` (`script:write`), отказ «Недостаточно прав» ответом,
  а не ошибкой сервера (`sceneNumbersAccessRefusal`) — и в авто-, и в ручной;
- авто (`planAutoRenumber`): живые сцены серии — 1, 2, 3… по порядку, номер, занятый вырезанной
  сценой, пропускается; номер вырезанной не меняется; порядок — позиция в серии вместе с вырезанными;
- ручная (`planManualRenumber`): номер вырезанной не меняется («Сцена 2 вырезана — её номер не
  меняется»); номер вырезанной другой сцене — отказ с буквой, как в импорте (`nextSceneNumber`):
  «Номер 2 занят вырезанной сценой — например, 2А»; повтор — «Номер 3 повторяется…» до записи;
  id строк — `assertInProject`. В окне у вырезанных поля номера неактивны, пометка «(вырезана)»;
- обмен 1 ↔ 2 (`applySceneNumberChanges`): **временные значения** в одной транзакции — сначала
  меняющим номер сценам `number = '~' || id`, затем новые номера одним `UPDATE … FROM unnest(…)`.
  Почему не отложенная проверка: уникальность сейчас — уникальный индекс Prisma
  (`@@unique`), а `DEFERRABLE` бывает только у ограничения — нужна миграция, и в схеме Prisma
  его не записать (расхождение схемы и базы при каждом `migrate dev`). Временные значения —
  только код, два запроса на любое число сцен, откат целиком при ошибке;
- обе перенумерации — под блокировкой строки проекта (как импорт): вторая вкладка ждёт.

**Отчёт смены** (`saveProductionSceneFactAction`, правило — `reports/lib/cut-scene-fact.ts`):
вырезанная сцена не в дне — отказ и на новую строку факта, и на правку уже сохранённой:
«Сцена N вырезана — верните её в либретто, чтобы записать факт». Проверка до записи и ещё раз
в транзакции под блокировкой строки сцены. Вырезанная в дне — факт пишется как есть.

**Удаление сцен** (`bulkDeleteScenesAction`, правило — `script/lib/scene-delete.ts`):
отказ целиком, если сцена стоит в дне КПП («Сцены 3, 7 стоят в днях КПП — уберите их из дня или
пометьте вырезанными»; у вырезанных — «уберите из дня») или есть строка отчёта смены / попытка
съёмки. Слот дня без связи с днём — не в счёт (ссылка в слоте обнуляется, как раньше). Окно
подтверждения получает строки отказа до нажатия из `getScenesDeleteImpactAction` (общий
компонент не менялся); сервер проверяет то же повторно в транзакции под блокировкой строк сцен.

| Проверка | Аккаунт | Результат |
|---|---|---|
| Авто-перенумерация (прямой вызов): 40, вырез. 37, 36 → 36, 37, 38 | Степа | так и стало, вырезанные 2 и 37 прежние; ответ «Нумерация обновлена» |
| Авто-перенумерация (прямой вызов) | a@a.ru «ТЕСТ без финансов» | «Недостаточно прав» |
| Ручная: сцена → 37 (номер вырезанной) | Степа | «Номер 37 занят вырезанной сценой — например, 37А» |
| Ручная: обмен 36 ↔ 38 | Степа | прошёл |
| Факт «снято» по вырезанной 37, строка факта есть, в дне нет | Степа | отказ, в базе без изменений (в день не попала, попытки нет) |
| Факт «снято» по вырезанной 2, стоит в дне 1 | Степа | сохранён |
| Удаление 38 + 37 (у 37 строка отчёта) | Степа | отказ в окне до нажатия и от сервера, ничего не удалено |
| Удаление 3 (в дне КПП) + 36 (только в слоте дня) | Степа | отказ по сцене 3, про 36 ни слова |
| Удаление 36 одной | Степа | удалена, слот остался со ссылкой «пусто» |

Прямой вызов авто-перенумерации: действие сейчас не импортирует ни один клиентский модуль, поэтому
его id нет в манифесте и снаружи оно не вызывается. Для проверки импорт временно добавлялся в
либретто и убран до коммита.

### Замечено, не тронуто
