# Волна 2в — заметки по шагам (для итогового отчёта, шаг 7)

## Шаг 3. Фин. поля не уходят в браузер без фин. прав

Общий помощник: `src/shared/lib/finance-fields.ts` — `pickFinanceFields(row, { open, finance }, canFinance)`.
Явный список разрешённых полей: поле не из списка не уходит никогда; без права фин. полей в
ответе нет совсем (не `null`). Тот же помощник — для записи: присланные фин. значения без
фин. правки отбрасываются до записи.

| Место | Что вырезано без права | Право | Как проверено |
|---|---|---|---|
| Кастинг: список, карточка кандидата | ставка, условия; снимок утверждённого актёра в карточку кандидата не отдаётся никому. Телефон, почта, агент — остаются | чтение: фин. просмотр актёров; запись: фин. правка актёров | RSC/HTML под a@a.ru; прямой вызов `updateCastingPersonAction` (a@a.ru — отказ, Степа — сохранено) |
| Персонажи: список, страница, «Утверждённый актёр (снимок)» | ставка, условия, налог, длительности из снимка; сырой `castSnapshot` не уходит никому (список его не использует) | то же | RSC/HTML под a@a.ru; `updateCharacterCastSnapshotAction` |
| Карточка актёра (страница персонажа) | ставка, налог, режимы, переработки, доп. выплаты, статьи сметы, «особые условия» | фин. просмотр актёров | RSC/HTML под a@a.ru |
| Карточка объекта, список объектов | ставка, налог, режимы, переработки, статьи сметы; стоимость в снимке скаута | фин. просмотр объектов; запись стоимости — фин. правка объектов | RSC/HTML; `updateLocationScoutSnapshotAction` |
| Карточка ресурса, страница категории | ставка, налог, км, режимы, переработки, доп. выплаты, статьи сметы | фин. просмотр категории | RSC/HTML под a@a.ru |
| Отчёт смены: строки | ставки, налог, оплата, доп. выплаты, км-ставка, итоги; почасовые ставки строки не уходят никому. Часы, переработка, км — остаются | строка видна: право просмотра источника или `finance:read`; деньги — фин. просмотр источника (актёр / категория / объект; спецтранспорт — `finance:read`) | RSC/HTML под a@a.ru, Степа — всё видно |
| Отчёт смены: доп. выплаты | запись | фин. правка источника | `saveProductionWorkExtrasAction` |
| Отчёт смены: «устарел» / «Ставки отличаются» | «было → стало» и оплата — только имя строки | фин. просмотр источника | RSC под обоими аккаунтами |
| Отчёт смены: «Обновить ставки» | галочка и запись | фин. правка источников всех строк с расхождением | `refreshProductionReportAction` |
| Ведомость по использованию | пункт меню и страница | фин. просмотр хотя бы одного источника (`canReadAnyEntityFinance`); спецтранспорт в ней — `finance:read` | меню и страница под a@a.ru |

Решение по ведомости: в ней только суммы (смены, переработки, доплаты, км, итоги) — строк без денег
там нет. Сводная уже фильтровала строки по праву источника, поэтому для роли без фин. прав она была
пустой страницей. Пункт меню и страница теперь — только при фин. просмотре хотя бы одного источника.
Правило спецтранспорта в ведомости приведено к отчёту смены (было «прочие ресурсы», стало `finance:read`).

Правка факта (часы, Т/О, км) без фин. прав работает как раньше; оплату сервер пересчитывает сам.
Строку, которую пользователь не видит, он и не правит (`updateProductionWorkRowAction`).

### Замечено, не тронуто
- Ставка за км в вызывном видна без фин. прав — в волну 3.
- Журнал прячет ставки отчёта смены (`rateChanges`) по `finance:read`, а не по праву источника строки.
- Списки «добавятся / уберутся / обновятся» в плашке «Отчёт устарел» показывают имена всех строк,
  в том числе тех, чей источник пользователь не видит (денег там нет).
- Выборки сцен (либретто, сценарий, КПП, вызывной) отдают в браузер полную запись персонажа
  (`character: true` — с сырым `castSnapshot`, в нём ставка и условия актёра) и полную запись
  позиции ресурса (`item` — ставка, км, налог). В вызывном ещё и полные записи актёров
  (`actor.findMany` в `getShootDayDocument`). Проверено RSC под a@a.ru: `castSnapshot.shiftRate`
  и `item.shiftRate` есть в либретто и КПП.

### Доработка шага 3
- Объект в выборках сцен (`script/queries.ts`, `schedule/queries.ts`, `day-docs/queries.ts`) —
  общий `SCENE_LOCATION_SELECT` из `locations/lib/location-fields.ts`: только открытые поля
  `LOCATION_FIELDS` (проверка типов не даст добавить фин. поле). Эти экраны денег объекта не
  показывают, поэтому фин. поля и снимок скаута не берутся из базы ни для кого.
- Скаут: стоимость в списке, карточке и форме — по фин. просмотру объектов (`SCOUT_CANDIDATE_FIELDS`);
  запись стоимости — с фин. правкой объектов (присланное без права отбрасывается).
- Утверждение кандидата кастинга: из браузера приходят только id, ставка и условия берутся из записи
  кандидата в базе. Оставлено как есть. Утверждение скаута — так же (стоимость из базы).
- Живая проверка записи под a@a.ru с ролью «правка без фин. условий»: кандидат, снимок персонажа,
  стоимость площадки, кандидат скаута (создание и правка) — прочие поля сохраняются, фин. значения
  в базе прежние; доп. выплата и «Обновить ставки» — отказ, в базе без изменений.
