## Задача 2. «Сохранить» при переходе по меню

**Сделано — в общем механизме** (`shared/ui/unsaved/`)
- Источник изменений может зарегистрировать функцию сохранения (успех / ошибка). При переходе по ссылке
  «Сохранить» появляется, только если сохраняться умеют все источники с изменениями. Они сохраняются по
  очереди; при первой ошибке остаёмся на месте.
- Пока идёт сохранение, кнопки неактивны («Сохранение…»), Esc и клик мимо окна не срабатывают.
- При ошибке вопрос закрывается, ошибку показывает форма; ошибка проверки в браузере — подсказка у поля.
- `useFormGuard(enabled, resetKey, saveState)`: форма передаёт состояние `useActionState`, механизм отправляет
  её как обычно и ждёт ответа с успехом (не дольше 30 с).
- Подключено:
  - настройки проекта;
  - карточка сцены;
  - персонаж (требования, снимок каста, гонорар);
  - локация (требования, снимок скаута, финансовые условия);
  - показатели дня отчёта смены;
  - редактор сценария.
- Редактор сценария сохраняет в текущую версию. У заблокированной версии (`isLocked`) «Сохранить» нет: страница
  даёт `canWrite` только при незаблокированной версии, и её текст не редактируется.

**Проверено в браузере:** вопрос с «Сохранить» на всех шести страницах. Ошибка проверки (пустое «Название»,
пустой «Номер» сцены): остаёмся, вопрос закрыт, подсказка у поля, на сервер ничего не ушло. Проверены
«Остаться» и «Не сохранять». Форма без регистрации (правка вызывного) — без «Сохранить»
(`img/wave-1b-save-prompt.jpg`, `img/wave-1b-save-validation-settings.jpg`).

**Не проверено:** успешное сохранение с переходом — на тот момент запись в базу была запрещена. Проверяет
владелец.

## Доп.: перерывы убраны из календаря проб

По решению владельца технические перерывы в планировании проб не нужны.

**Убрано:** блок «Технические перерывы» в плане дня, окно перерыва, показ перерывов на шкале дня и недели,
перерывы в экспорте расписания проб (Word и печать), серверные действия «добавить / изменить / удалить
перерыв», запрос списка перерывов и их тип. Подсказки над календарём больше не упоминают перерывы.

**Не тронуто:** таблица перерывов в базе и записи в ней (если есть — просто не показываются); шаблоны
перерывов в вызывном — другой экран; запись «Перерыв в пробах» в журнале изменений оставлена, чтобы старые
записи журнала показывались с понятным названием.

**Проверено:** план недели и дня открываются, блока перерывов нет; окно экспорта открывается; экспорт
собирается в HTML и Word на тестовых данных (без перерывов). Из чек-листа ручной проверки пункт «окно
перерыва» больше не нужен.

## Замечено по ходу, не тронуто

- Предупреждение библиотеки перетаскивания о несовпадении идентификаторов при загрузке (КПП, либретто) —
  «1 Issue» в режиме разработки; было до волны.
- `deleteCastingPersonAction` (удаление кандидата кастинга) после удаления неиспользуемого импорта не
  вызывается нигде в интерфейсе — кнопки удаления кандидата нет. Аудит в нём добавлен; удалять или подключать —
  решение владельца. `addCastingApplicationAction` используется в карточке кандидата.
- Отзыв приглашения («Отозвать») — без подтверждения: это не удаление, приглашение остаётся отменённым.
- В проекте сейчас 1 участник: второй аккаунт удалён из проекта не мной (владелец проверял удаление участника).

## Ручная проверка (для владельца)

| Что | Как |
|---|---|
| Меню и «Обзор» по правам | Вторым аккаунтом под разными ролями |
| «Участники» без права | Прямая ссылка → «Нет доступа» |
| «Сохранить» при переходе | Правка → меню → «Сохранить»: сохранено и переход; ошибка сервера → остались |
| Удаления | Окно, числа, отказы; снятая сцена → отказ с номерами; удаление участника |
| Тёмная тема | Поля дат, «Неделя», основная кнопка, звёзды |
| Ничего не сломалось | Персонажи, сцены, кастинг, сценарий, окна с формами (задача 6) |
