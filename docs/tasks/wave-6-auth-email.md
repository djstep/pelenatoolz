# ЧАСТЬ 1. ИНСТРУКЦИЯ

## Что получится

- Письма из системы: подтверждение почты, сброс пароля, «пароль изменён», приглашение в проект. Русские шаблоны, HTML + простой текст.
- Требования к паролю: от 10 символов, не из списка частых паролей, не совпадает с почтой. Без «обязательно заглавная и цифра» — это ослабляет пароли (люди пишут `Password1!`).
- Подтверждение почты при регистрации. Без подтверждения войти нельзя, на странице входа — «Отправить письмо ещё раз».
- Сброс пароля по ссылке из письма: ссылка на 1 час, одноразовая. После сброса все сессии выходят.
- Смена пароля в профиле (с вводом текущего), если её ещё нет.
- Приглашение в проект на почту: письмо со ссылкой на 7 дней, роль выбирается при приглашении. В «Участниках» — статус приглашения (отправлено / принято / истекло / отменено), «Отправить ещё раз», «Отменить».
- Ограничение попыток: вход, сброс, повторная отправка писем.

**Чего не будет.** Входа через Яндекс/Google/Telegram, двухфакторной защиты, смены почты в профиле — отдельно, если понадобится.

## Подготовка

1. Почтовый сервис — **Resend** (решено), бесплатный тариф: 3 000 писем в месяц, не больше 100 в день. Подключение через его SMTP — код не привязан к Resend, перед реальными людьми меняется на российский сервис (Unisender Go) одними настройками.
   - Зарегистрироваться на resend.com, создать API-ключ (права «Sending access»).
   - В `.env` и в Vercel: `MAIL_TRANSPORT=smtp`, `SMTP_HOST=smtp.resend.com`, `SMTP_PORT=465`, `SMTP_USER=resend`, `SMTP_PASSWORD=<API-ключ>`, `MAIL_FROM="ФИЛЬМТУЛЗ <noreply@твой-домен>"`, `APP_URL=<адрес прода>`. В `.env.e2e` — `MAIL_TRANSPORT=dev` (e2e не должны тратить лимит 100 писем в день).
   - До этого Claude Code работает с «почтовым ящиком для разработки» — письма пишутся в базу/файл, а не уходят.
2. Домен. Resend без своего домена отправляет только на почту владельца аккаунта Resend — для проверки хватит, для приглашений других людей нет. В Resend → Domains добавить домен (лучше поддомен, например `mail.povpro.ru` или домен системы, когда будет), прописать у регистратора DNS-записи, которые выдаст Resend (SPF, DKIM, MX для поддомена), плюс DMARC. Дождаться статуса «Verified».
3. Ветка базы dev/e2e — миграции будут (токены, приглашения, счётчики попыток).
4. Файл в `docs/tasks/wave-6-auth-email.md`, коммит в `main`. Новая сессия Claude Code, Opus, усилие высокое.

- Изменения данных — через `auditMutation`. В журнал: регистрация, подтверждение почты, сброс и смена пароля, приглашение (кто, кого, какая роль), принятие, отмена.

## Безопасность — обязательно

- Токены (подтверждение, сброс, приглашение): случайные 32 байта, в базе хранится только хеш (SHA-256), сравнение по хешу. Срок: подтверждение 24 ч, сброс 1 ч, приглашение 7 дней. Одноразовые: после использования — отметка `usedAt`. Новый токен того же типа для того же человека гасит старые.
- Токены и пароли не попадают в логи, журнал, ошибки, URL-параметры кроме самой ссылки из письма.
- Ответы не выдают, есть ли такая почта в системе: «Если такой адрес зарегистрирован, мы отправили письмо» — одинаково для любого адреса, одинаковое время ответа (отправку письма не ждать в запросе, либо выравнивать).
- После сброса пароля и после смены — все сессии пользователя недействительны (кроме текущей при смене).
- Ограничение попыток хранится **в базе** (Vercel без общей памяти): вход — 5 неудач за 15 мин на пару «почта + IP», затем блок 15 мин; запрос сброса — 3 в час на почту; повторная отправка подтверждения/приглашения — 3 в час. Сообщение при блоке — без подробностей.
- Пароль: от 10 до 128 символов; не из списка частых паролей (локальный файл, топ 10 000, без внешних запросов); не равен почте и её части до `@`. Подсказка надёжности на форме — без внешних пакетов, если можно. Существующие пароли не трогать: правила действуют при следующей смене.
- Алгоритм хеша паролей — проверь на шаге 0. Если не bcrypt (cost ≥ 12) или argon2id — предложи переход (перехеширование при следующем входе), жди «да».

## Шаг 1. Почтовый слой и шаблоны

- `src/shared/mail/`: одна функция `sendMail({ to, subject, html, text })`. Транспорт по `MAIL_TRANSPORT`: `smtp` (переменные `SMTP_*`, `MAIL_FROM`; сейчас это SMTP Resend — `smtp.resend.com`, порт 465, пользователь `resend`, пароль — API-ключ) или `dev` — письмо пишется в таблицу/файл «ящика разработки» и в консоль. По умолчанию в dev и e2e — `dev`. SDK Resend не ставить: только `nodemailer` по SMTP, чтобы смена сервиса была заменой переменных.
- Лимит бесплатного Resend — 100 писем в сутки. Ошибку превышения лимита (ответ SMTP) распознать и записать в лог отдельным понятным сообщением, пользователю — общее «не удалось отправить письмо, попробуйте позже».
- Для e2e — способ прочитать последнее письмо на адрес (хелпер в `e2e/`), чтобы тесты переходили по ссылке из письма.
- Ошибка отправки не роняет действие пользователя: пишется в лог (без токена), пользователь видит общее «не удалось отправить письмо, попробуйте позже», где это уместно.
- Шаблоны: подтверждение почты, сброс пароля, пароль изменён, приглашение в проект. Общий каркас: название системы, текст, кнопка-ссылка, та же ссылка текстом, «если это были не вы — проигнорируйте». Без картинок с внешних адресов, без счётчиков открытий. Ссылки строятся от `APP_URL`, не от заголовков запроса.
- Страница разработчика для просмотра «ящика» — только при `MAIL_TRANSPORT=dev` и не в production-сборке.

## Шаг 2. Пароль и ограничение попыток

- Правила пароля — одна функция, используется в регистрации, сбросе, смене, принятии приглашения. На клиенте — те же правила для подсказки, на сервере — проверка обязательна.
- Ограничение попыток — таблица + функция `checkRateLimit(key, limit, window)`; старые записи чистятся при обращении (без фоновых задач).
- Применить ко входу, запросу сброса, повторным отправкам.

## Шаг 3. Подтверждение почты

- Поле `emailVerifiedAt` у пользователя (если нет). Миграция: всем существующим — дата миграции.
- Регистрация → письмо со ссылкой → страница подтверждения → вход. Без подтверждения вход отклоняется с понятным текстом и кнопкой «Отправить письмо ещё раз».
- Принятие приглашения по ссылке из письма подтверждает почту (адрес тот же).
- Согласие на обработку персональных данных при регистрации: галочка, текст-ссылка на страницу политики. Текст политики — заглушка с пометкой «нужен текст юриста», страница доступна без входа. Без галочки регистрация не проходит.

## Шаг 4. Сброс и смена пароля

- «Забыли пароль?» на странице входа → почта → одинаковый ответ → письмо → страница нового пароля (правила шага 2) → все сессии вышли → письмо «пароль изменён» → вход.
- Профиль: смена пароля с текущим паролем. Текущая сессия остаётся, остальные выходят. Письмо «пароль изменён».

## Шаг 5. Приглашения на почту

- При приглашении: почта + роль (как сейчас выбирается роль). Письмо с названием проекта, кто пригласил, ролью и ссылкой.
- По ссылке:
  - почта уже зарегистрирована → вход (если не вошёл) → «Принять приглашение» → участник проекта;
  - не зарегистрирована → регистрация с этой почтой (поле заблокировано), почта считается подтверждённой → участник.
  - вошёл под другой почтой → сообщение «приглашение для другого адреса», кнопка «Выйти и войти как …».
- Истёкшее, отменённое, уже принятое — понятные сообщения, без раскрытия деталей проекта.
- «Участники»: список приглашений со статусом, «Отправить ещё раз» (новый токен, старый гаснет, лимит шага 2), «Отменить». Права — как у приглашения сейчас.
- Существующий способ приглашения (если сейчас это ссылка для копирования) — оставить рядом, если он есть: «Скопировать ссылку» тоже работает. Если убрать — спроси.

2. Ручная проверка безопасности по списку «Безопасность — обязательно» — таблица «пункт → где в коде → проверено тестом/вручную».
