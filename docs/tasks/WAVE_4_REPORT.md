### Защита

1. **`contentHtml` блоков сценария хранится как прислал браузер** (пункт 4 аудита, не закрыт полностью). Шаг 7 закрыл показ в редакторе (только разрешённая разметка, из узлов), импорт и синхронизация `contentHtml` не пишут. Но серверное действие сохранения версии (`src/features/screenplay/actions.ts`, схема `contentHtml: z.string().max(500_000)`) принимает любой HTML, и в базе он лежит как есть. Любое новое место показа через `innerHTML` снова откроет дыру. **Сделать до реальных пользователей:** очищать `contentHtml` на сервере при записи тем же списком тегов (`safe-block-html.ts`) и почистить уже сохранённые блоки (решение владельца 11).
2. **Кнопка «Экспорт» в окнах выгрузки пишет в проект** (`Project.exportSettings` сохраняется перед скачиванием, шаг 5). Выгрузка — чтение; проверить, какое право нужно для этой записи и не меняет ли настройки проекта участник с правом только просмотра.
3. **Печать через `document.write` в пробах, кастинге, выгрузке сцен и роли** (`schedule-export-modal.tsx`, `cast-list-export-modal.tsx`, `script-export-modals.tsx`, `character-script-button.tsx`). В шаге 7 проверены только сценарий, сцены и роль (текст экранируется, название проекта в печати сценария теперь тоже); пробы и кастинг не проверялись.
4. **`Scene.scriptContent` принимается серверными действиями создания и правки сцены**, если прислать напрямую (полей в интерфейсе нет, шаг 6а). Не права, а лишние данные от браузера: поле перезапишется следующим импортом, но до него в либретто будет чужой текст.

### Не работает или работает не везде

10. **Предел размера сценария.** Ответ предпросмотра ≈ 1,3 × `document.xml` (ddct: 105 КБ → 133 КБ), у Vercel потолок ответа — 4,5 МБ. Поэтому сервер после распаковки отклоняет `document.xml` больше 3 МБ (`SCRIPT_DOCUMENT_XML_MAX_BYTES` в `normalize/docx-zip.ts`): «Сценарий слишком большой для импорта…». Ответ тогда не больше ~4 МБ. Обычный полный метр (`document.xml` 1–1,5 МБ) проходит с запасом. На VPS предел можно поднять (раздел 10 «На переезд»).
11. **PDF / печать в редакторе сценария** не открывалась (`noopener`) — исправлено в шаге 7, но во встроенном браузере не проверить (он не открывает окна). **Проверить в Chrome** (владелец).

## 2. Архитектура конвейера (кратко)

```
docx → (браузер) облегчение → (сервер) распаковка с лимитами → абзацы → типы блоков → нормализация → экран проверки → запись
                                                                                 ↑                               │
                                                                          словарь проекта ←────── решения (только при записи)
```

- **Облегчение** (шаг 7, `normalize/docx-slim.ts`): в браузере, исходный до 50 МБ, на сервер — только текстовые части и связи, до 3,5 МБ.
- **Распаковка** (`normalize/docx-zip.ts`): своя, по центральному каталогу, `zlib` с лимитами (30 МБ всего, 1000 частей, `document.xml` ≤ 20 МБ). Пункт 20 аудита закрыт. Предел импорта — `document.xml` ≤ 3 МБ (п. 10).
- **Абзацы** (`docx-paragraphs.ts`, `docx-numbering.ts`): правки (track changes), скрытый текст, автонумерация Word.
- **Типы блоков** (`block-types.ts`): стили Word → отступы → текст; расхождение уровней — вопрос.
- **Нормализация** (`normalize-script.ts` и соседние): символы, титульная, шапки, персонажи, реплики, переходы, похожие имена (`similar.ts`), словарь (`dictionary.ts`), сопоставление со сценами проекта (`scene-match.ts`), хронометраж совпавших сцен (шаг 7). Чистые функции, одинаково на сервере и в браузере.
- **Вопросы:** постоянные (в словарь) и разовые (по сцене); обязательные блокируют импорт, пока нет ответа пользователя.
- **Предпросмотр** ничего не пишет: сервер разбирает файл один раз и отдаёт блоки с типами, словарь, записи проекта, хэш и id текущей версии; вопросы и «было → стало» считает браузер.
- **Запись** (`write/plan.ts`, `write/apply.ts` — `writeScript`): одна функция для импорта и «Обновить в либретто». Сервер получает только файл, ответы, правки титульной, хэш и id версии и разбирает всё заново. Одна транзакция с блокировкой проекта и сверкой версии, записи пачками. Одна запись в журнале.
- **Хронометраж** — `estimateSceneTiming` по режиму проекта, формула не менялась.
