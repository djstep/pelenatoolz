## 0. «Экспорт → Печать / PDF» вызывного на проде не открывалась

**Причина — две, обе в коде печати:**

1. **Шрифт не находился на Vercel.** Лист для печати встраивает шрифт Medeo, а путь к файлу шрифта искался через `createRequire(…).resolve("medeo-font/fonts/…")` — через карту `exports` в `package.json` пакета. В сборку Vercel (`outputFileTracingIncludes`) попадает только сам файл `.woff2`, без `package.json` пакета, поэтому поиск падал с `MODULE_NOT_FOUND`. Серверное действие печати бросало исключение, а меню его не ловило (`void printCallSheet()`): окна нет, сообщения нет — «тишина». Excel шрифт не использует — поэтому работал. Тем же путём шрифт читает маршрут `/api/fonts/…` (шрифт листа на странице) — на проде он тоже падал, лист на странице показывался запасным шрифтом.
   - Как проверено: копия собранного сервера (`.next/standalone`) в отдельной папке, где нет исходного `node_modules`, — до исправления `resolve` → `MODULE_NOT_FOUND` (на копии `node_modules` сборки); после исправления сервер из такой папки отдаёт шрифт: 200, 338 864 байт, `font/woff2`. Локально (`next dev`, `next start` в папке проекта) ошибка не видна: Node находит пакет в `node_modules` проекта.
2. **Окно открывалось после ответа сервера.** `window.open` стоял после `await` — блокировщик всплывающих окон разрешает окно только в обработчике клика (Safari — строго сразу, Chrome — несколько секунд). На медленном ответе (холодный старт, ~470 КБ HTML) окно блокировалось бы и при исправном шрифте.

**Исправление** (коммит `c0258ef`, только эти файлы — пойдёт в `main` отдельно):
- `medeo-font.ts`: путь — прямой, от корня проекта, ровно тот, что в `outputFileTracingIncludes` (`node_modules/medeo-font/dist/fonts/medeo-sans/MedeoSansVariable.woff2`). Сверка путей кода и `next.config.ts` — в тесте.
- `print-window.ts` → `printServerHtml`: окно открывается сразу по клику (до запроса к серверу), в нём «Готовим лист к печати…»; потом пишется лист и вызывается печать. Ответ с ошибкой или исключение — окно закрывается, пользователь видит сообщение («Браузер не открыл окно печати — разрешите всплывающие окна», текст ошибки сервера или «Не удалось подготовить лист к печати — попробуйте ещё раз»).
- `print-actions.ts`: сбой сборки листа — ответ `{ error }` и запись в лог сервера (`[call-sheet print]`), а не исключение.
- То же для «Печать» утверждённой версии из списка версий — та же функция `printCallSheet`.
- Тест `call-sheets/print/print-window-open.test.ts`: шрифт находится в папке, где есть только файл шрифта (как в сборке Vercel); окно открывается до запроса к серверу; ошибка и исключение закрывают окно; меню и список версий вызывают печать без `await` до окна. В браузере (Playwright, Chromium) — окно открывается, лист со встроенным Medeo, «ЧЕРНОВИК», версия из списка — с «версия N · утверждён».

**После деплоя проверить:** «Печать / PDF» и «Печать» версии в Chrome на проде; в Vercel → Logs нет `[call-sheet print]`.

## 6. Как запускать снова

Нужны запущенный `npm run dev` (порт 3000; другой — переменная `E2E_BASE_URL`) и `.env` с адресом ветки e2e. Одна команда:

```bash
npm run e2e
```

Она создаёт аккаунты и проект, если их нет (пароли — в `.env.e2e`), входит под тремя ролями и прогоняет все тесты. Отчёт — `playwright-report/index.html`, скриншоты — `e2e/screenshots/`. Чистые данные: `npm run e2e:reset`, затем `npm run e2e`. На новой машине сначала `npx playwright install chromium`.
