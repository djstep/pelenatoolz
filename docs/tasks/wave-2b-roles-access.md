# ЧАСТЬ 1. ИНСТРУКЦИЯ

## Что получится

- В редакторе ролей каждое право — один флажок, без повторов.
- Отказ сервера при сохранении роли не стирает то, что ты ввёл.
- В журнале видно, кто принял приглашение. Видны и другие изменения участия: смена роли, удаление, возврат.
- Цифры на «Обзоре» показываются только по разделам, которые роль видит.
- В кастинге можно удалить кандидата — с подтверждением и записью в журнал.
- Форматирование блоков сценария чистится на сервере: опасный HTML в базу больше не попадает, старые блоки вычищены.
- Выгрузка («Экспорт») не меняет настройки проекта у тех, у кого нет права правки.
- Печать в пробах и кастинге не выполняет HTML из имён и текстов.
- Сервер не принимает текст сцены от браузера в карточке сцены.

## Зачем до волны 3

Волна 3 раздаёт доступы к папкам Google Диска по ролям и цехам. Права и журнал к этому моменту должны быть надёжными: флажок должен значить то, что на нём написано, а каждая смена участия — оставлять след. Защита — потому что дальше в систему придут реальные люди.

## Задача 6. `contentHtml` блоков сценария — очистка на сервере

Отчёт волны 4, раздел 1, п. 1. Сейчас серверное действие сохранения версии (`src/features/screenplay/actions.ts`, `contentHtml: z.string().max(500_000)`) принимает любой HTML, и в базе он лежит как есть. Показ в редакторе уже безопасный (`src/features/screenplay/lib/safe-block-html.ts`), но любое новое место показа через `innerHTML` снова откроет дыру.

Сначала покажи мне:
- все места, где `contentHtml` пишется в базу (сохранение версии, копирование версии, создание из либретто, что ещё есть);
- как сделать очистку на сервере без новых пакетов: на сервере нет DOM. Варианты — свой разбор тегов по тому же списку, что `safe-block-html.ts`, или общий модуль, который работает и в браузере, и на сервере. Предложи один, с обоснованием;
- сколько блоков с непустым `contentHtml` сейчас в базе (по проектам) — запросом только на чтение.

Требования:
- Один список разрешённого для браузера и сервера: теги b, strong, i, em, u, s, strike, del, span, font, div, p, br; цвет текста и фона — только `#rgb`, `#rrggbb`, `rgb()`, `rgba()`. Всё остальное — текстом (как в редакторе), атрибуты кроме цвета — выбрасываются.
- Очистка — во всех местах записи `contentHtml`. Если после очистки форматирования не осталось — пишется пусто (`null`), а не обёртка без смысла.

Результат серверной очистки на тех же входах совпадает с тем, что показывает редактор (`safe-block-html.ts`).
- **Чистка уже сохранённых блоков** — скриптом в `scripts/`. Сначала пробный прогон без записи: сколько блоков изменится, по проектам, 3–5 примеров «было → стало» (без текста сценария целиком — только фрагмент вокруг изменения). Запись — после моего «да». Повторный запуск ничего не меняет.
- Проверка в браузере: блок с жирным, курсивом, цветом и фоном — сохранить в версию → в базе то же форматирование. Прямой вызов сохранения с `<img src=x onerror=…>` в `contentHtml` → в базе текст без тега.
