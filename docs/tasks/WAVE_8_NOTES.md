# Волна 8 — рабочие заметки

Итог будет в `WAVE_8_REPORT.md`.

## Ответы владельца на шаге 0

1. Должность вписывается в окне «Подтянуть», договор не меняем.
2. Цех выбирается в том же окне; подстановка по статье сметы из начислений договора, можно сменить.
3. ООО в «Подтянуть» нет. Физлица, самозанятые, ИП есть. ООО-человека добавляют вручную и связывают с договором, берём только телефон и почту.
4. Показываем все договоры, кроме «Отклонён»; статус виден рядом. Договор стал «Отклонён» — запись остаётся с пометкой.
5. «Подтянуть» и данные договора — по «Договоры и акты: просмотр», «Финансы» не требуем. Сумм в команде нет ни у кого. Тестовый аккаунт без договоров и без контактов заменяет проверку «без финансов».
6. Меню: «Планирование», сразу после «Вызывных», `/crew`.

Добавлено владельцем:
- Телефон и почта в «Подтянуть» — только при «Команда: контакты». Без флага окно работает, но контакты не показывает и **не сохраняет**.
- Разобранные ФИО, телефон, почта — предложение: редактируемые поля в окне до сохранения.
- Без дублей: повторное «Подтянуть» не создаёт второго человека. Похожее ФИО — предложить связать договор с существующим. Один человек может быть связан с несколькими договорами.

## Решения шага 1

- «Название для титров» (`creditsName`): подпись формы без пояснений, по смыслу — имя для титров, а не должность; в базе dev заполнено у 0 из 2 договоров. Как предложение должности не подставляем.
- Вместо `contractId?` и `counterpartyId?` из ТЗ — таблица связей `CrewMemberContract`: так требует «один человек — несколько договоров». Один договор может быть у нескольких людей (сотрудники одного ООО), поэтому уникальна пара «человек + договор». Ограничения «контрагент — один человек» и «повторное Подтянуть» проверяет действие на шаге 3 в транзакции.
- Основной договор не хранится: это самый новый не «Отклонён» из связанных.
- Удалили договор — связь ушла. `source = CONTRACT` без связей = пометка «договор удалён».
- `syncedValues` — снимок для «меняли вручную», в браузер не отдавать.
- Журнал ролей пишет только «Изменена роль …», без списка флагов: новые права попадают туда автоматически.

## Решения шага 2

- Миграция проверена: права выдаются по правилу (`isSystem` и имя «Продюсер», остальным просмотр), конкретных id ролей в ней нет.
- `toCrewRow` (`crew-rules.ts`) — единственное место, где запись становится строкой для браузера. Запрос читает всё, поля перечислены явно. Шаг 4 (экспорт) идёт через него же.
- Поиск только в браузере, серверного поиска нет.
- Журнал: смена телефона и почты пишется как «скрыто → скрыто», значений нет. Номера договора в журнале на шаге 2 нет; при «Подтянуть» (шаг 3) номер кладётся в `changes` и вырезается без права на договоры.
- `sortOrder`: 0 у всех = порядок не меняли, идёт по фамилии. Перетаскивание нумерует с 1. Новый человек после перетаскивания встаёт в конец цеха.
- Порядок — только внутри цеха. Цех меняется в карточке.
- Сид: 4 договора (физлицо К1, самозанятый К2, ИП К3, ООО К4), люди «Светов» (по К1) и «Вручнов» (вручную). К2 и К3 — для шага 3. Аккаунт `e2e-crewonly`.

## Решения шага 3

- Сид договоров: запуск только руками, `npm run e2e` и `npm run e2e:reset`. В `vercel-build`, `prisma.config.ts` и `package.json` сида нет, `vercel.json` и `.github` нет, в миграциях тестовых договоров нет. В начале сида — отказ при адресе прода `ep-steep-sound`. Эта проверка знает только нынешний адрес: при переезде на VPS её надо обновить.
- Колонка «Цех» убрана: при поиске группы не схлопываются, заголовок цеха остаётся.
- Строка окна «Подтянуть» — контрагент, а не договор: один контрагент — один человек. Отмеченная строка связывает все его свободные не отклонённые договоры.
- Дубли проверяет транзакция: строки контрагентов блокируются (`FOR UPDATE`), затем заново смотрим, есть ли контрагент в команде. Если есть, договор только связывается, даже если браузер прислал «создать».
- «Похожий человек»: фамилия совпадает, имя и отчество не спорят (инициалы подходят). Телефон сравнивается только при «Команда: контакты». Архив учитывается. По умолчанию выбрано «Связать», «Добавить отдельно» — осознанный выбор.
- Снимок при «Подтянуть» — значения договора, а не правки в окне: иначе правка в окне не считалась бы ручной. Без права на контакты телефона и почты нет ни в записи, ни в снимке. Позже у пользователя с правом они выглядят как новые данные договора и отмечены.
- Галочка в «Обновить»: только если изменилось в договоре и не меняли вручную. Поле, опустевшее в договоре, показывается, но не отмечено. Один номер в другом написании разницей не считается. Цех и должность не сверяются: их нет в договоре.
- Что не применили, в снимке не меняется и будет показано снова.
- «Связать с договором» данные не копирует и снимок не трогает, ставит `source = CONTRACT`: иначе после удаления договора не было бы пометки. Заполненные вручную поля в первом «Обновить» не отмечены, пустые отмечены.
- Занятый контрагент (физлицо, самозанятый, ИП уже у другого человека) в «Связать» не предлагается, сервер отказывает. У ООО людей может быть несколько.
- Номер договора в журнале — в `changes.fields.Договор`, без права на договоры вырезается (`entity-access.ts`). В `summary` номера нет.
- Цех в окне — по статье сметы самого частого начисления договора, при равенстве более свежего. Начисления, обнулённые отчётом смены, не считаются. Суммы не читаются.
- Окна «Связать» и «Обновить» идут поверх карточки. После «Обновить» карточка закрывается: её поля заполнены старыми значениями.

## На следующие шаги

- Шаг 5: полный e2e покажет, не мешает ли 4-й тестовый аккаунт тестам Диска (`c3`–`c6`, `c9`–`c11`), где считаются участники.
- Пометка «договор удалён» появляется, когда не осталось ни одной связи. Связь с удалённым договором уходит вместе с ним (решение шага 1), поэтому удаление одного из нескольких договоров не видно.
- Несохранённые правки в карточке теряются, если там же нажать «Обновить из договора» и применить: окно закрывается без вопроса.
