## Модель данных (принята)

- **`Department` (цех)**: projectId, name, codePrefix, sortOrder, createdAt/updatedAt. `name` и `codePrefix` уникальны в проекте. Цех — новая модель (категории ресурсов, `DepartmentCallTime`, роли — не цех). Тот же цех в волне 3 для вызывных. Удалить цех нельзя, если есть смета/версии (со шага 2).
- **`DepartmentHead`**: departmentId + membershipId (участник проекта, не пользователь), пара уникальна, каскад с цехом и участником. Доступ — только активным участникам.
- **`Budget`** (существующая книга Univer) + `departmentId` обязательный и уникальный (одна книга на цех), `mainSheetId` (основной лист, удалить нельзя), статус `DRAFT / SUBMITTED / RETURNED`, кто/когда/комментарий отправки и возврата, `revision` (растёт при каждом сохранении; продюсер утверждает ту правку, которую видел).
- **`BudgetItem`** (статья, живая запись): projectId, departmentId, code, name, текущие значения черновика, `archivedAt`. Код уникален в проекте. Разбор основного листа — на сервере при сохранении.
- **`BudgetVersion`** (утверждённая версия, неизменяемая): цех, книга, номер (уникален в цехе), approvedById (пользователь), approvedAt, итог, снимок основного листа. Действий изменить/удалить нет.
- **`BudgetVersionLine`**: ссылка на `BudgetItem` по id + копия: код, наименование, ед., кол-во, ставка, дни, сумма, налог %, налог, итого, порядок.
- **`Accrual.budgetItemId`** и **`CashPaymentBreakdown.budgetItemId`** — необязательные ссылки по id на живую статью (пусто = «без статьи»). План — из последней утверждённой версии. Разбивка платежа по нескольким статьям остаётся; неразнесённый остаток платежа = «без статьи».
- **Статья убрана из черновика** → не удаляется, ставится `archivedAt`; факт остаётся на ней; в План/факт — «вне плана». Код = личность статьи: тот же код под другую статью нельзя; повторный ввод кода возвращает ту же статью (тот же id). При возврате архивной статьи с фактом — предупреждение в проверках + аудит. Смена кода в строке = новая статья, факт остаётся на старой.
- **Флаг «Сметы — просмотр всех»**: новый раздел матрицы `smeta_all`, только «Доступ» + «Просмотр». Миграция данных по образцу `20261027200000_contracts_permission_section`: всем ролям выключен, системному «Продюсеру» включён. Исключить из шаблона «Наблюдатель» для новых проектов (`buildViewerMatrix` включает все разделы). Правило пакета 5 работает через `isPermissionSubset` автоматически.
- **Меню**: поле `headDepartmentIds` в `NavAccess`, отдельной логики нет. Пункт называется «Сметы».
- **`budget` (вкладка «Статьи») уходит в шаге 4**: `BudgetLine`, enum `BudgetCategory`, `BudgetLineType`, `BudgetLinkedResourceType`, связи Project/Counterparty/Accrual/CashPaymentBreakdown. Данных: 0 статей, 0 начислений, 0 платежей. «Плановый контрагент» и «тип статьи» не нужны. Переменные СМЕНЫ/СЕРИИ останутся только в настройках финансов.
- **Уведомлений в проекте нет** — только статус на экране.

- Себя главой назначает только продюсер (не-продюсер с «управление участниками» может назначать других).

- Переходы (всё под блокировкой строки сметы `SELECT … FOR UPDATE`, сохранение тоже):
  - глава: черновик/возвращена → на утверждении. Нельзя: заголовки сломаны, нет статей, нет отличий от последней версии, ревизия не совпала (сначала досохраняется);

## Шаг 4 — решения владельца

- Статьи в выпадающих списках — только из смет, которые пользователь видит (бухгалтеру — флаг «Сметы — просмотр всех»).
- Начисления из отчёта смены — по видам: смена, переработка, доплаты, км. У актёра, ресурса и объекта статья по умолчанию на основную оплату (смена и доплаты) и необязательные статьи для переработки и км (у ресурса); пусто — основная.
- Сумма без налога в отчёте считается точно (по каждой части со своим налогом).
- «Оплачено» у начисления не определяется. Строку отчёта обнулили или удалили — начисление не удаляется: сумма 0, пометка «обнулено в отчёте», запись в журнал. Такое начисление удаляется руками. Связь платежа с конкретными начислениями — не в этой волне.
- Платёж без контрагента не проводится (проверка на сервере).
- Статья создаётся только при заполненных коде и наименовании; код без наименования — только подсветка в проверках.

## Шаг 4 — отчёт смены без записи при открытии

Решения владельца: открытие отчёта ничего не пишет (ни строки, ни начисления, ни журнал); пересборка — только «Обновить из КПП» и «Создать из КПП», только с правом правки отчёта; при сохранении строки полной пересборки нет.
