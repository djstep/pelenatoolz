# Волна 2 — принятые решения

Итоги шага 0 (план модели данных) и ответы владельца. ТЗ — `docs/tasks/wave-2-smeta.md`.

## Модель данных (принята)

- **`Department` (цех)**: projectId, name, codePrefix, sortOrder, createdAt/updatedAt. `name` и `codePrefix` уникальны в проекте. Цех — новая модель (категории ресурсов, `DepartmentCallTime`, роли — не цех). Тот же цех в волне 3 для вызывных. Удалить цех нельзя, если есть смета/версии (со шага 2).
- **`DepartmentHead`**: departmentId + membershipId (участник проекта, не пользователь), пара уникальна, каскад с цехом и участником. Доступ — только активным участникам.
- **`Budget`** (существующая книга Univer) + `departmentId` обязательный и уникальный (одна книга на цех), `mainSheetId` (основной лист, удалить нельзя), статус `DRAFT / SUBMITTED / RETURNED`, кто/когда/комментарий отправки и возврата, `revision` (растёт при каждом сохранении; продюсер утверждает ту правку, которую видел).
- **`BudgetItem`** (статья, живая запись): projectId, departmentId, code, name, текущие значения черновика, `archivedAt`. Код уникален в проекте. Разбор основного листа — на сервере при сохранении.
- **`BudgetVersion`** (утверждённая версия, неизменяемая): цех, книга, номер (уникален в цехе), approvedById (пользователь), approvedAt, итог, снимок основного листа. Действий изменить/удалить нет.
- **`BudgetVersionLine`**: ссылка на `BudgetItem` по id + копия: код, наименование, ед., кол-во, ставка, дни, сумма, налог %, налог, итого, порядок.
- **`Accrual.budgetItemId`** и **`CashPaymentBreakdown.budgetItemId`** — необязательные ссылки по id на живую статью (пусто = «без статьи»). План — из последней утверждённой версии. Разбивка платежа по нескольким статьям остаётся; неразнесённый остаток платежа = «без статьи».
- **Статья убрана из черновика** → не удаляется, ставится `archivedAt`; факт остаётся на ней; в План/факт — «вне плана». Код = личность статьи: тот же код под другую статью нельзя; повторный ввод кода возвращает ту же статью (тот же id). При возврате архивной статьи с фактом — предупреждение в проверках + аудит. Смена кода в строке = новая статья, факт остаётся на старой.
- **Флаг «Сметы — просмотр всех»**: новый раздел матрицы `smeta_all`, только «Доступ» + «Просмотр». Миграция данных по образцу `20261027200000_contracts_permission_section`: всем ролям выключен, системному «Продюсеру» включён. Исключить из шаблона «Наблюдатель» для новых проектов (`buildViewerMatrix` включает все разделы). Правило пакета 5 работает через `isPermissionSubset` автоматически.
- **Меню**: поле `headDepartmentIds` в `NavAccess`, отдельной логики нет. Пункт называется «Сметы».
- **`budget` (вкладка «Статьи») уходит в шаге 4**: `BudgetLine`, enum `BudgetCategory`, `BudgetLineType`, `BudgetLinkedResourceType`, связи Project/Counterparty/Accrual/CashPaymentBreakdown. Данных: 0 статей, 0 начислений, 0 платежей. «Плановый контрагент» и «тип статьи» не нужны. Переменные СМЕНЫ/СЕРИИ останутся только в настройках финансов.
- **Уведомлений в проекте нет** — только статус на экране.

## Ответы владельца

- Старые 2 книги смет (12 листов, без цеха) — удалить миграцией в шаге 2 (разрешено). `departmentId` обязательный.
- Правка во время утверждения: статус → «черновик», смета остаётся в списке продюсера с пометкой «изменена после отправки», «Утвердить» только у отправленной.
- Шаблоны: основной лист всегда из встроенного шаблона; свои шаблоны (`BudgetTemplate`, 0 шт.) убрать.
- `Payment` из отчёта смены — вариант Б (шаг 4): отчёт смены создаёт посменное начисление со ссылкой на строку отчёта, таблица `Payment` удаляется. Контрагент у такого начисления необязателен: подбирается у актёра/ресурса, если нет — пометка «контрагент не указан». «Ввод по сменам» показывает, что смена уже начислена из отчёта. Справка: `Payment` пишется только `src/features/reports/lib/sync-payment.ts`, нигде не читается, в базе 2 записи.
- «Ввод по сменам» в шаге 4 возвращается через «статью по умолчанию» у актёра и ресурса: строки для них, подсказка контрагента (история/совпадение имени) и налога, сумма по ставке смены.
- Проверки при сохранении (не блокируют): дубль кода в проекте; сумма без кода; код без наименования; код пропал из основного листа, а по нему есть факт → «код X исчез, по нему факт N ₽, станет "вне плана"».
- Смена префикса цеха не трогает существующие коды, новый префикс только для новых строк.
- Префикс: 2–6 символов, буквы или цифры (кириллица/латиница), заглавные, первая — буква.
- Себя главой назначает только продюсер (не-продюсер с «управление участниками» может назначать других).
- Удаление участника снимает его со всех глав — пишется в аудит (удаление мягкое, статус `REMOVED`, повторное приглашение возвращает ту же запись membership).
- Тестовый аккаунт главы заводит владелец. Пароли и данные входа никуда не записывать.

## Шаг 2 — итог

- Миграция `20261029150000_department_budgets`: удалены 2 старые книги и `BudgetTemplate`; `Budget` + `departmentId` (один на цех), `mainSheetId`, `revision`; `BudgetSheet` + `sheetKey` (уникален в книге); новая `BudgetItem`. Ссылки на цех и основной лист — `NO ACTION` (проверка в конце запроса): удаление проекта каскадом проходит, отдельно цех со сметой и основной лист не удалить.
- Шаблон основного листа: `Код статьи · Наименование · Ед. · Кол-во · Ставка · Дни/смены · Сумма · Налог, % · Налог · Итого`, строка заголовков закреплена. Защита заголовков — правило защиты диапазона Univer при открытии (правка, удаление защиты запрещены); удалить/вставить/сдвинуть колонку внутри блока нельзя, удаление основного листа отменяется (`BeforeSheetDelete`).
- Код `ПРЕФИКС-ГГ.СС`. Автокод — только когда в строке появилась Ставка (значение или формула): раздел = ближайший код выше, номер = max в разделе + 1 (учитываются архивные). Стёр автокод — метка строки `smetaNoAutoCode` в `rowData`, код больше не ставится. Вместе с кодом в пустые ячейки ставятся формулы Сумма/Налог/Итого.
- Разбор на сервере при каждом сохранении, по заголовкам. Раздел (без ставки и кода) и подытог (СУММ/SUM по диапазону в Сумме или Итого без кода) — не статьи, без проверок. Кол-во/Ставка/Дни/Налог % — вычисленные значения ячеек (в т.ч. формулы со ссылкой на другие листы); Сумма/Налог/Итого сервер считает сам (пустые Кол-во и Дни = 1). Сломаны заголовки — лист сохраняется, статьи не трогаются, кнопка «Восстановить заголовки».
- Статьи: новый код — новая статья; пропал — `archivedAt`; вернулся (тот же код) — та же запись. Аудит «Смета цеха» — одна запись на сохранение, только если изменились статьи; создание сметы — отдельная запись.
- Проверки (не блокируют): дубль кода на листе и в проекте, сумма без кода, код без наименования, число в Сумме/Итого не совпадает с расчётом, не число в числовой колонке. Панель «Проверки: N» под шапкой, клик — переход к строке, подсветка строк (`range.highlight`, в книгу не пишется). Считаются при сохранении и при открытии.
- Дыра с листами закрыта: лист ищется только по паре «книга цеха + `sheetKey`», серверный id листа в браузер не уходит, ключи проверяются (`[A-Za-z0-9_-]{1,64}`, без повторов, не больше 100 листов).
- Убраны: страница и окно шаблонов, мастер «Новая смета», переключатель книг, переименование, «В шаблон», импорт (вернётся в шаге 6). Страницы: `/smeta` (цеха, статьи, итог, «Создать смету» у главы), `/smeta/[departmentId]` (редактор; продюсер и «просмотр всех» — только чтение).
- Проверено в браузере под главой «Художественного»: создание сметы, защита A1, меню защищённой колонки без «Удалить/Вставить столбец», удаление основного листа недоступно; смета с разделом, тремя статьями и подытогом (итог 65 200 ₽ сходится со списком); Ставка `=Лист1!B2` → 1500 и автокод; стёртый код не возвращается, предупреждение «сумма без кода»; ручной ввод прежнего кода восстанавливает архивную статью; чужой цех по прямой ссылке — 404. Атака подменой листа (скриптом через `persistDepartmentBudget`: ключ и серверный id листа книги «Звука») — лист «Звука» не изменился, подложенное стало новыми листами своей книги; тестовая книга «Звука» удалена.
