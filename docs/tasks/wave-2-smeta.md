# ЧАСТЬ 1. ИНСТРУКЦИЯ

## Что получится

- У каждого цеха своя смета. Её правит глава цеха, чужие сметы цех не видит.
- Продюсер видит все сметы, но листы цехов не правит. Он утверждает или возвращает их с комментарием.
- План — последняя утверждённая версия сметы цеха. Глава правит черновик, правки уходят на утверждение, продюсер видит, что изменилось.
- У каждой строки сметы есть постоянный «код статьи». Начисления и платежи ссылаются на код.
- Отчёт «План/факт»: по каждой статье план, начислено, оплачено, остаток, перерасход. Строки «без плана» и «вне плана».
- Сводная книга продюсера: лист на каждый цех и лист «Свод».
- Вкладка «Статьи» уходит.
- Заодно лечим автосохранение сметы: сейчас она гоняет всю книгу на сервер каждые 2,5 секунды.

## Подготовка

1. Волна 1 и волна 1б (хвосты волны 1) закончены и слиты в `main`. Фильтр меню по правам из волны 1б нужен шагу 1.
2. Новая сессия Claude Code (`/clear`), Opus, усилие высокое. На шаге 0 (план модели данных) можно включить сверхвысокое.
3. База тестовая, миграции разрешены, но только файлами миграций.

## Шаг 1. Цеха и доступ

## Шаг 2. Смета цеха по шаблону

- При создании сметы цеха лист создаётся из шаблона с обязательными колонками (заголовки защищены от удаления и переименования):
  `Код статьи · Наименование · Ед. · Кол-во · Ставка · Дни/смены · Сумма · Налог, % · Налог · Итого`.
  Сумма, Налог и Итого — формулы. Можно добавлять свои колонки справа и свои листы-черновики, но учитываются только строки основного листа с заполненным кодом.
- Код статьи: предложи формат с префиксом цеха (например `ХУД-02.03`) и автоподстановку следующего номера при добавлении строки. Ручной ввод разрешён.
- Проверки при сохранении (не блокируют, а подсвечивают и показывают список): дубль кода в проекте; сумма есть, а кода нет; код есть, а наименования нет.
- Разбор строк в статьи — на сервере при сохранении, не на клиенте.
- Наименование статьи меняется — код остаётся, связи с платежами не рвутся.

## Шаг 3. Утверждение и версии

- Глава: кнопка «Отправить на утверждение» (необязательный комментарий). Пока смета на утверждении, глава может продолжать править — тогда статус возвращается в «черновик», продюсер видит, что смету меняли после отправки.
- Продюсер: список смет на утверждении. Экран сравнения «последняя утверждённая ↔ текущий черновик» по строкам: добавлено, удалено, изменено (было → стало по сумме и итогу), итог по цеху было → стало.
- «Утвердить» создаёт неизменяемую версию (шаг 0). Перед созданием — подтверждение: «Создать версию N? Отменить нельзя». «Вернуть» — с обязательным комментарием, глава его видит.
- Первая смета цеха без утверждённой версии — план пустой, все траты в отчёте «без плана».
- История версий цеха: список, просмотр любой версии только на чтение.
- Уведомление внутри системы главе и продюсеру о смене статуса — если в проекте уже есть механизм уведомлений; если нет — только статус на экране, скажи мне.

## Шаг 5. План/факт и сводная книга

**План/факт** (отдельный экран, в ячейки сметы ничего не пишется):
- по каждой статье: план (из последней утверждённой версии), начислено, оплачено, остаток = план − начислено, % исполнения; перерасход подсвечен;
- итоги по цеху и по проекту;
- строки «Без плана» (факт по коду, которого нет в утверждённой версии) и «Без статьи» (начисления/платежи без кода);
- статья убрана из новой версии, а факт по ней есть — строка остаётся, помечена «вне плана»;
- фильтры: цех, период по дате начисления/платежа;
- глава видит свой цех, продюсер и флаг «просмотр всех» — всё;
- выгрузка в Excel (ExcelJS, на сервере).

**Сводная книга продюсера** (только чтение):
- лист на каждый цех — последняя утверждённая версия; переключатель «показать черновики»;
- лист «Свод»: цех, план, начислено, оплачено, остаток;
- выгрузка в Excel.
