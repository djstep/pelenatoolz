# Ручная проверка пакетов 4, 3, 5

Где: локально, `http://localhost:3000`, ветка `fix/security-batch`. Вход под своим аккаунтом (продюсер).

**База общая с сайтом.** Всё, что создадите, появится на сайте. Создавайте записи с пометкой «ТЕСТ» в названии, после проверки удалите по списку в конце. Записи журнала аудита удалить нельзя, это нормально.

Общее правило для пакета 4: обычные действия должны работать как раньше. Ответ «Объект не найден» на своих данных — это ошибка, пришлите скриншот.

## Пакет 4. Ссылки между сущностями

**Договоры и акты** (Контрагенты → Договоры / Акты)
- [ ] Создайте договор «ТЕСТ»: компания, контрагент, статус, тип ведомости, теги. Сохраните, откройте снова — всё на месте.
- [ ] В том же договоре смените контрагента и статус, сохраните — изменения сохранились.
- [ ] Создайте акт «ТЕСТ», привязанный к этому договору. Если есть тестовый платёж — и к платежу. Сохраняется, компания и контрагент подставились из платежа.
- [ ] В форме договора у контрагента нажмите «+», введите название «ТЕСТ контрагент» и нажмите **Enter**. Контрагент создаётся и сразу выбран в поле. Это исправление entity-picker.

**Кастинг и актёры**
- [ ] Препродакшн → Кастинг: добавьте человека «ТЕСТ» с привязкой к персонажу — создаётся.
- [ ] Пробы: создайте пробу «ТЕСТ» на персонажа, при возможности — со сценой. Создаётся.
- [ ] Актёры: создайте актёра «ТЕСТ» с персонажем, затем измените его — сохраняется.
- [ ] Утверждение кандидата — **только на тестовом персонаже**. Утверждение отклоняет остальных кандидатов этого персонажа и перезаписывает карточку персонажа, откатить это кнопкой нельзя. Ожидаем: появился актёр, у персонажа обновилась карточка.

**Либретто и сценарий**
- [ ] Либретто: у тестовой сцены смените объект, персонажей, элементы, сохраните — изменения на месте.
- [ ] Сценарий: в шапке сцены измените ИНТ/НАТ, место, режим. Сохраните версию — изменения видны в либретто после синхронизации.
- [ ] Наоборот: измените сцену в либретто — шапка в сценарии обновилась.
- [ ] Сценарий → синхронизация с либретто: предпросмотр открывается, применение проходит без ошибки.
- [ ] Сохраните версию сценария обычным сохранением — без ошибок, текст и привязка блоков к сценам на месте. Здесь было исправление: чужой номер сцены из браузера больше не принимается.
- [ ] Оставьте комментарий к фрагменту текста и ответьте на него — оба появились.

**Вызывной** (Вызывные → тестовый день)
- [ ] Добавьте таймслот со сценой, сохраните — слот на месте.
- [ ] Добавьте актёра в вызывной и уберите его — сохраняется.
- [ ] Посменные ресурсы: измените время, сохраните.
- [ ] Пересчёт таймингов актёров: предпросмотр → применить — тайминги обновились.

## Пакет 3. Вход, редиректы, облако

**Адрес возврата после входа.** Выйдите из аккаунта, затем открывайте ссылки:
- [ ] `http://localhost:3000/ru/login?callbackUrl=/ru/projects` → войдите → попадаете на список проектов.
- [ ] `http://localhost:3000/ru/login?callbackUrl=//example.com` → войдите → попадаете на `/ru/projects`, **не** на example.com.
- [ ] `http://localhost:3000/ru/login?callbackUrl=https://example.com` → войдите → `/ru/projects`.
- [ ] `http://localhost:3000/ru/login?callbackUrl=/\example.com` → войдите → `/ru/projects`.
- [ ] Регистрация с `?callbackUrl=//example.com` ведёт себя так же. Это создаст новый аккаунт: делайте только если готовы его потом удалить через базу.

**Облачные диски — локально не проверить.** В локальном `.env` нет ключей Google и Яндекса, кнопка «Подключить» ответит «GOOGLE_CLIENT_ID не настроен». Проверять на сайте после переноса в main:
- [ ] Файлы → подключить Google Диск → дать согласие → **возврат на ту же страницу** с отметкой «подключено», без страницы ошибки. Раньше здесь, скорее всего, была ошибка.
- [ ] То же для Яндекс Диска.
- [ ] Начните подключение, на экране согласия Google **выйдите из PELENA в другой вкладке**, потом дайте согласие → возврат на `/ru/projects?cloud_error=state`, диск не подключился.
- [ ] По желанию: начните подключение, подождите на экране согласия больше 10 минут, потом согласитесь → `cloud_error=state`.
- [ ] Уже подключённые диски открывают список файлов. Если нет — проверьте на Vercel длину `CLOUD_TOKEN_SECRET` или `AUTH_SECRET`, нужно не меньше 32 символов.

## Пакет 5. Роли и участники

Под продюсером (Участники и роли):
- [ ] Откройте роль «Продюсер» и нажмите сохранить → «Системную роль изменить нельзя». То же для «Наблюдатель».
- [ ] Создайте роль с названием «продюсер» (строчными) → «Это название зарезервировано для системной роли».
- [ ] Создайте роль «ТЕСТ роль» с парой прав → создаётся.
- [ ] Переименуйте «ТЕСТ роль» в «Наблюдатель» → отказ. Измените её права → сохраняется.
- [ ] В списке участников попробуйте сменить роль **себе** → «Нельзя изменить свою роль».
- [ ] Создайте приглашение с ролью «Наблюдатель» → ссылка создана. Не делайте его с «ТЕСТ роль»: роль, на которую ссылается приглашение (даже отозванное), база не даст удалить.
- [ ] Откройте ссылку приглашения, будучи уже в проекте → «Вы уже участник проекта», ваша роль не изменилась. Ссылка строится от `APP_URL`, а локально это боевой сайт. Замените в ссылке `https://pelenatoolz.vercel.app` на `http://localhost:3000`, иначе откроется сайт со старым кодом.
- [ ] Отзовите это приглашение.
- [ ] Удалите «ТЕСТ роль» → удаляется.
- [ ] Журнал аудита: есть записи «Роль» (создана, изменена, удалена) и «Приглашение» (создано, отозвано). В подробностях нет почт и телефонов.

## Без второго аккаунта проверить нельзя

Нужен второй пользователь в проекте с ролью вроде «Координатор»: управление участниками есть, но прав меньше, чем у продюсера. Пригласить его — это новая запись в боевой базе.

- Координатор не может создать или изменить роль с правами шире своих → «Нельзя выдать права шире ваших собственных».
- Координатор не может пригласить или назначить роль шире своих прав, в том числе «Наблюдатель», если у него нет просмотра всех разделов.
- Координатор не может менять роль или удалять продюсера → «…с правами шире ваших».
- Координатор не может править роль, которую носит сам → «Нельзя изменить роль, которая назначена вам».
- Последний продюсер. Второй продюсер не может понизить или удалить вас, если вы единственный продюсер. Если продюсеров двое, понизить одного можно.
- Принятие приглашения новым пользователем: участник создаётся с ролью из приглашения, в аудите есть запись «Участник».
- Приглашение на конкретную почту не принимается под другой почтой.

Через обычный интерфейс не проверить (нужен второй проект и подмена запроса в инструментах разработчика):
- пакет 4 — подстановка id из чужого проекта в договоры, кастинг, сцены, вызывной;
- пакет 3 — привязка диска по чужой ссылке подключения, кроме варианта с выходом из аккаунта выше.
